## 最常见的几种写错法（对照着看）

你现在没贴代码，我先按常见场景给你几种“可能的坑”，你对照一眼就知道是哪一种了。

### 1）props 叫 `order`，却写成 `t.xxx`

比如我们之前常用这种写法：

```ts
const OrderCard: React.FC<{ order: Order }> = ({ order }) => {
  return (
    <div>
      {/* ✅ 正确 */}
      <div>{order.productName}</div>
      <div>{order.status}</div>
    </div>
  );
};
```

如果你现在里面写成：

```ts
<div>{t.productName}</div>   // ❌ t 根本不存在
```

就会直接报你这个错。

✅ 修改方式：把所有 `t.xxx` 改成 `order.xxx`（或你真实的 props 名字）。

---

### 2）map 回调里乱用 t，当成变量名但没定义

比如：

```ts
orders.map((order) => (
  <OrderCard key={order.id} order={order} />
));
```

如果你在 `OrderCard` 里写了：

```ts
const badge = t.status === 'ACTIVE' ? '生效中' : '已结束'; // ❌
```

但你根本没有：

```ts
const t = ...;
```

那也会直接炸。

✅ 修改方式：同样，把 `t.status` 改成 `order.status` 或 props 里真实的名字。

---

### 3）引入了 `t('xxx')` 这种写法，但没引 i18n 的 t

比如你写了：

```ts
<span>{t('order.status.active')}</span> // ❌
```

但是没有：

```ts
import { useTranslation } from 'react-i18next';

const { t } = useTranslation();
```

那浏览器就会说：`t 是谁？？`

两种解决：

- 暂时不用多语言：**直接改成字符串**：

  ```ts
  <span>生效中</span>
  ```

- 或者：真的要用 i18n，就在组件顶部加上：

  ```ts
  import { useTranslation } from 'react-i18next';

  const OrderCard: React.FC<{ order: Order }> = ({ order }) => {
    const { t } = useTranslation();
    // ...
  };
  ```
