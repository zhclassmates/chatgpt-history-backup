## 🎁 交付方式分类（虚拟产品）

| 类型 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 1. **视频交付（作品型）** | 以视频方式呈现 App 效果（演示 + 解说 + 拍反应） | 无需开发上线即可交付；适合娱乐传播 | 用户无法亲自体验；只是内容消费 |
| 2. **H5 网页交付（轻量试玩型）** | 把App做成网页，用链接扫码/点击打开 | 跨平台、无需安装；只需一个服务器 | 不适合复杂交互；需解决服务器长期存在 |
| 3. **小程序交付（中度交互型）** | 微信/支付宝/抖音小程序；用户搜索或扫码即用 | 适合国内生态；更新快；不需安装 | 有平台审核限制，功能限制多 |
| 4. **APP交付（重度应用型）** | 真正的App，发布到App Store/安卓商店 | 最完整的交互体验 | 开发周期长；审核严格；需版本维护 |
| 5. **网站集合交付（数字作品图鉴型）** | 所有无用App集中在一个网站展示+试玩+收藏 | 可持续运营；形成系列；用户可二刷 | 初期需要设计信息架构，可能冷启动难 |
| 6. **NFT/虚拟装置交付（实验/收藏型）** | 把App作为“数字行为艺术”通过NFT或网页封装 | 有稀缺性；艺术价值；可拍卖/收藏 | 更适合小众路线，用户不一定理解 |

## 📱 如何让虚拟App“在手机上存活”

这取决于你希望它“活多久”，以及“是否允许反复访问”：

### 🔹 **1. 持续可访问性：用网站 + 网页App**
- 将每个无用App做成单页面 Web 应用（HTML + JS）
- 使用类似 [Vercel](https://vercel.com/)、[Netlify](https://www.netlify.com/)、GitHub Pages 等托管
- 用一个统一的网址管理（比如：`wuyong-apps.fun`）
- 每个小程序一个子页面，用户可收藏/分享链接

> 例子：`https://wuyong-apps.fun/breathe-to-open`

### 🔹 **2. 小程序方式：利用平台活力**
- 微信小程序 + 抖音小程序是国内最易让人“记住”的路径
- 用户通过收藏/最近使用访问，无需安装
- 可以设置随机入口、周更App、一键试玩等形式

> 推荐做成**“无用实验室”小程序**，所有小程序都在里面，有种“数字废物图鉴”的感觉

### 🔹 **3. 视频即交付：以“行为作品”呈现**
- 如果你把这些App当成“数字表演”，完全可以只通过视频传播
- 用户无法操作，但你用拍摄+解说+反应完成“交付”
- 可通过网站或频道归档所有“数字废物成果”

## 🧩 扩展灵感：如何让“无用”更有生命力？

- “App即烟火”：使用一次就炸掉，下一次要重新生成
- “七日App”：每个App只存在7天，倒计时结束后网站自动清除
- “观众共创”：用户投票决定下一个App功能，然后上线试玩

- “反安装机制”：App运行完后弹窗说：“现在你该删掉我了”

国外主流社交 App 在手机端“存活”靠的是**从安装、打开、日常使用，到后台推送和持续更新**一整套生态设计。以下分几个层面来聊他们都怎么做的，并举几个海外的创意玩法：  

---

## 一、分发与安装：铺天盖地的触点  
1. **应用商店优化（ASO）**  
   - 在 App Store / Google Play 上架后，持续优化标题、关键词、截图和评价，让用户更容易搜索到并下载。  
2. **深度链接 & 联盟推广**  
   - 朋友圈、微博、YouTube、博客文章里都可嵌入“打开 App”或“去下载”的深度链接，一键直达对应内容页。  
3. **预装 & 合作渠道**  
   - 部分品牌手机（如三星、小米国际版）会预装 Facebook、Instagram 等；也会和运营商、内容平台合作推广安装包或流量包。

---

## 二、留存与唤醒：千钧一“推”  
1. **个性化推送通知**  
   - 新消息、好友动态、内容推荐，精准触发；并且 A/B 测试通知文案、图标、发送时机，不断提升打开率。  
2. **小红点 & Badge 机制**  
   - App 图标或 Tab 栏上永不消失的小红点，让用户感觉“必点一下”。  
3. **应用内消息 & Inbox**  
   - 除了系统通知，还会在 App 内部展示“你错过了 n 条好友动态”“XX 刚对你点赞”等提醒。  

---

## 三、用户体验 & 核心功能：让你停不下来  
| 手段              | 作用                       | 经典案例                          |
|-------------------|----------------------------|-----------------------------------|
| **算法推荐**      | 内容精准推送，提升粘性     | Instagram Explore、Facebook Feed |
| **短视频/故事**   | 碎片化内容、随时刷不停     | IG Stories、TikTok、Snapchat      |

## 四、后台技术保证：24/7 在线  
1. **自动更新**  
   - 用户同意后，App Store/Play Store 会在后台自动更新到最新版本，无需用户手动干预。  
2. **离线缓存 & 本地存储**  
   - 用户上次看过的 Feed、消息、已点赞内容，都会缓存在本地，保证无网络时也能打开 App，提升可用性。  
3. **后台消息拉取**  
   - iOS/Android 后台静默推送（silent push），在你不知情的情况下拉取最新内容，保证你下次打开时立刻有新东西。

## 五、国外创意玩法举例  
1. **“每日话题挑战”**  
   - Instagram 的“每日话题”（Daily Prompt），每天给你一个拍照/视频主题，鼓励 UGC。  
2. **快闪滤镜活动**  
   - Snapchat 与电影、品牌联动，推出限时 AR 滤镜，制造“错过即绝版”的氛围。  
3. **地理打卡集章**  
   - TikTok 地点挑战：用户到某个城市/地标拍视频即可获得专属标签，刺激线下社交。  
4. **可定制化头像框**  
   - Facebook、Twitter 在重大节日或公益活动时，用户可为头像加彩带或框，产生社交扩散。  

---

## 六、小结与启发  
- **分发→留存→唤醒→体验→再更新**，构成完整闭环。  
- **千万不要让 App“石沉大海”**：从小红点推送到算法推荐、从自动更新到离线缓存，每一步都在提醒用户“来看看”。  
- **抓创意，用限时／稀缺＋二创**：快闪活动、AR 滤镜、话题挑战……不断制造“FOMO”（害怕错过），让用户保持新鲜感。

你可以借鉴他们的三大杀手锏：  
1. **精准推送＋小红点**：第一时间把你拉回 App；  
2. **算法推荐＋短视频**：短平快、可刷可玩；  
3. **限时／稀缺活动**：创造话题，让用户“恐慌性”打开。

结合“无用 App”概念，你也可以：  
- 推送“你错过了 X 个无用实验”，  
- 用限时“7 天挑战”机制让每个 H5 小程序自动到期，  
- 借助 AR/滤镜让用户给无用工具拍趣味短视频……  

如此，你的“无用”就更“有料”地活在用户手机里。

## 一、核心玩法框架

1. **双人共触触发**

   - 利用 HTML5/微信小程序 的多点触控事件 (`touchstart`) 来检测“至少两个不同 touch.identifier”同时按下。  

2. **心率/生理信号触发**  
   - **方案 A**：摄像头+闪光灯 PPG 心率检测  
     - 让参与者轮流把食指盖在摄像头和闪光灯上，采集 15 秒视频，计算心跳间隔 → 心率值。  
     - 利用现成 JS 库（如 `heart-rate-monitor.js`）或小程序插件（如「拍照心率」）快速接入。  
   - **方案 B**：外部蓝牙心率带  
     - 通过 Web Bluetooth 或小程序蓝牙 API 连接 Polar、Mi Band 等设备，获取实时心率。  
     - 适合有硬件的场景，可做更精确的数据触发。  

3. **随机触发 / 游戏继续**  
   - **投卦/随机数**：  
     - 根据“两个触点按下时长”“两次心率值之和”或“心跳间隔随机取余”，生成一个 1–6 的数字 → 构成六爻（或一次投卦）。  
   - **问答/小游戏**：

## 1. 动作 & 传感器映射

| 拟
交互动作       | 传感器           | 原理 & 检测方法                                              |
|------------------|------------------|-------------------------------------------------------------|
| **拧动手机**     | 陀螺仪           | 检测绕 Z 轴（屏幕垂直轴）的角速度（rotationRate.alpha），累积转过一定角度就触发。 |
| **敲击/磕头**    | 加速度计         | 检测短时大幅加速度突变（acceleration）或力反馈（force），阈值峰值即可判定敲击一次。     |

| **晃动/摇一摇**   | 加速度计         | 经典的“摇一摇”逻辑：检测双向反复加速度变化（阈值+方向变化次数）触发。                 |

## 3. 核心逻辑示例

以下是一个极简 H5 “转一圈出扭蛋”逻辑伪码：

```js
let totalRotation = 0;
let lastAlpha = null;
window.addEventListener('deviceorientation', e => {
  if (lastAlpha !== null) {
    // 计算这次与上次的最短角度差
    let delta = (e.alpha - lastAlpha + 540) % 360 - 180;
    totalRotation += Math.abs(delta);
  }
  lastAlpha = e.alpha;
  // 如果累计旋转超过 360°
  if (totalRotation >= 360) {
    triggerGashapon();   // 播放扭蛋动画
    totalRotation = 0;
  }
});
```

你只需把 `triggerGashapon()` 中换成“随机选一个彩蛋 → 显示弹窗／动画”，就大功告成。

## 3. 软件端检测＋触发逻辑示例

```js
let accSum = 0;
window.addEventListener('devicemotion', e => {
  // 累加三个轴的绝对加速度
  const a = Math.abs(e.acceleration.x) 
          + Math.abs(e.acceleration.y) 
          + Math.abs(e.acceleration.z);
  accSum += a;
  // 当累积值超过阈值，触发效果
  if (accSum > 500) {
    showRandomEgg();
    accSum = 0;
  }
});
```

- **调整阈值**（这里用 `500` 只是举例）来匹配小车速度或滚动流畅度。

## 4. 注意事项与优化

1. **稳固度**：手机与载体间要加足缓冲（海绵、硅胶垫），避免振动使手机卡死或掉落。  
2. **传感器校准**：不同机型灵敏度不一样，上线前做好多次测试并调节阈值。  
3. **电量&散热**：长时间运动会让手机发热，尤其放在球体内；可以做短时“游戏回合”设计。  
4. **用户提示**：在 App 开头提示“请确保手机已牢固固定，否则运动中可能掉落造成损伤”。

## 二、前端 H5 代码示例

下面是一个最小可用的 HTML+JS 演示页面，手机浏览器（Chrome/Edge for Android、Safari for iOS 16.4+）均可运行。

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>SmartBall Controller</title>
</head>
<body>
  <h2>智能球控制</h2>
  <button id="btnConnect">连接球体</button>
  <p id="status">未连接</p>

  <script>
  const serviceUuid       = '6e400001-b5a3-f393-e0a9-e50e24dcca9e';
  const rxCharUuid        = '6e400002-b5a3-f393-e0a9-e50e24dcca9e';
  let rxCharacteristic;

  document.getElementById('btnConnect').addEventListener('click', async () => {
    try {
      const device = await navigator.bluetooth.requestDevice({
        filters: [{ namePrefix: 'SmartBall' }],
        optionalServices: [serviceUuid]
      });
      const server = await device.gatt.connect();
      const service = await server.getPrimaryService(serviceUuid);
      rxCharacteristic = await service.getCharacteristic(rxCharUuid);
      document.getElementById('status').textContent = '已连接';
      startOrientationControl();
    } catch (err) {
      console.error(err);
      alert('连接失败：' + err);
    }
  });

  function sendCmd(cmd) {
    if (!rxCharacteristic) return;
    const data = new TextEncoder().encode(cmd);
    rxCharacteristic.writeValue(data);
  }

  function startOrientationControl() {
    let lastGamma = null;
    window.addEventListener('deviceorientation', e => {
      if (lastGamma === null) {
        lastGamma = e.gamma;
        return;
      }
      const delta = e.gamma - lastGamma;
      lastGamma = e.gamma;
      // 根据左右倾斜控制转向
      if (delta > 5)      sendCmd('R');  // 右转
      else if (delta < -5) sendCmd('L'); // 左转
      else                 sendCmd('F'); // 前进（轻微前倾也可改为检测 beta）
    });

    // 当不倾斜时停止
    window.addEventListener('deviceorientation', e => {
      if (Math.abs(e.gamma) < 3 && Math.abs(e.beta) < 3) {
        sendCmd('S');
      }
    });
  }
  </script>
</body>
</html>
```

### 运行流程

1. **打开页面** → 点击「连接球体」，授权蓝牙配对。  
2. **页面监听 `deviceorientation`**：  
   - 手机向右倾斜（`gamma` 增大）→ 发送 `'R'` → 球体右转  
   - 手机向左倾斜（`gamma` 减小）→ 发送 `'L'` → 球体左转  
   - 手机保持水平且无大幅转动 → 发送 `'S'` → 球体停止  

你也可以根据`acceleration`事件改成“摇动”或“敲击”触发其他动作。

## ✅ 一、太阳能板能不能给手机充电？

### ✅ 可行，但有严格条件：

1. **太阳能电压必须稳定在 5V 左右**
2. **有保护电路，避免过压、欠压、反流**
3. **必须加“稳压模块”（如 5V 升压 + 限流芯片）**
4. **不能直接接在手机上！否则⚠️可能烧坏设备**

---

## ⚠️ 手机充电的核心问题：不是“有电”就行，而是：

| 参数 | 要求 | 原因 |
|------|------|------|
| 电压 | 必须稳定在 5.0V ± 0.25V | 否则手机拒绝充电或烧坏 |
| 电流 | 至少 0.5A（充电慢），建议 ≥1A | 电流太小可能不识别 |
| 稳定性 | 电压波动不能大 | 否则触发手机保护电路 |
| 反向保护 | 太阳能弱时，防止手机反放电 | 否则电池倒灌危险 |

---

## ☀️ 如果你用一个“小太阳能板”，比如“功夫板”：

### 情况一：☀️白天强光

- 功夫板发出电压 ≈ 5.5V~6.5V，电流也许有 100~300mA；
- ⚠️ **如果直接接手机，很危险** → 电压太高 + 无控制；
- ✅ 加一个**稳压模块（比如 AMS1117-5.0 或 USB充电模块）**，才能安全输出 5V

---

### 情况二：🌥️ 阴天或室内

- 功夫板输出电压可能掉到 2~4V；
- 手机直接接上不认，会断充；
- ⚠️ 更严重：若没有保护电路，**手机可能反向放电进太阳板，烧毁板子或手机**

---

## ✅ 正确做法：**用太阳能给电池充电 → 再给手机充电**

推荐结构：

```
太阳能板 → 充电管理模块（如 TP4056）→ 锂电池 → 升压模块（MT3608）→ USB → 手机
```

### 推荐模块功能：

| 模块 | 作用 |
|------|------|
| TP4056 + 保护板 | 给锂电池安全充电 + 过充过放保护 |
| MT3608 升压模块 | 把锂电池的 3.7V 升到 5V |
| USB 输出口 | 稳定提供 5V 给手机 |
| 功夫板 6V 2W+ | 给 TP4056 供电（需强光） |

> ✅ 这样做不会烧手机，可以慢慢充（适合户外应急、环保发电等）

---

## 🚫 不推荐直接接的情况：

| 行为 | 风险 |
|------|------|
| 太阳板直接接手机 | 电压不稳烧手机主板 |
| 没有升压模块就接电池 | 电压低手机无法识别 |
| 没保护电路反向放电 | 手机电池倒灌，短路烧芯片 |

### 可用指标包括：
| 指标 | 表征方式 | 手机/工具能否监测 |
