## 1 Python SDK（脚本或服务器端调用）

1. **要求**：Python ≥ 3.9  
2. **安装**  
   ```bash
   pip install -U google-genai     # 官方 SDK
   ```
3. **最小示例**  
   ```python
   import google.generativeai as genai
   genai.configure(api_key=os.getenv("GEMINI_API_KEY"))
   model = genai.GenerativeModel("gemini-1.5-pro-latest")
   print(model.generate_content("Hello, Gemini!").text)
   ```  
   这就是完整调用流程：配置 → 选模型 → 发消息 → 取 `.text`。citeturn0search0

> **提示**：想要流式输出时，把 `model.generate_content(..., stream=True)` 然后遍历结果即可。

---

## 2 Gemini CLI（跨平台终端助手）

1. **要求**：Node.js ≥ 18  
2. **安装**（两选一）  
   ```bash
   # 直接用 npx（零安装）
   npx https://github.com/google-gemini/gemini-cli

   # 或全局安装
   npm install -g @google/gemini-cli
   ```
3. **首次运行**  
   ```bash
   gemini                     # 或 npx ... 同上
   ```
   首次会提示登录 Google 账号并读取你已设置的 API Key。之后就可以在任何 Shell 里用自然语言写代码、调命令，甚至配合 MCP 插件拉取网页实时信息。citeturn0search2turn1news9

> **常用快捷**  
> - `gemini -p "用 Python 写个快速排序"` 一次性输出  
> - `gemini --shell`             让 Gemini 帮你逐行解释错误并给出修复指令

## 4 常见问题（FAQ）

| 问题 | 解决办法 |
|---|---|
| **国内网络连不上** | 你现在在韩国，直连 Google 一般没问题；如果回到中国大陆需自备梯子。 |
| **CLI 提示没找到 API Key** | `echo $GEMINI_API_KEY` 查看是否漏掉引号或终端没重开。 |
| **SDK 长时间空等待** | 确认模型名称写得对（如 `gemini-1.5-pro-latest`），并检查提示词是否过大（> 32 k tokens 会被截断）。 |

### 1. **Git 项目（使用 Git 管理）**
如果你的项目已经在 Git 仓库中，修改本地项目通常包括以下步骤：

#### 修改文件：
1. **进入项目目录**

   ```bash
   cd /path/to/your/project
   ```

   ```bash
   git status
   ```

3. **编辑文件**  
   使用你喜欢的编辑器（如 VS Code、Sublime Text、Vim）修改代码：
   ```bash
   code .
   ```

4. **查看代码差异**  
   在提交之前，你可以查看你修改的代码差异：
   ```bash
   git diff
   ```

5. **提交更改**  
   当你完成编辑后，使用 Git 提交你的更改：
   ```bash
   git add .
   git commit -m "你的提交信息"
   ```

6. **推送更改**  
   如果你需要将修改推送到远程仓库：
   ```bash
   git push origin main  # 或者你使用的其他分支名称
   ```

#### 合并或分支管理：
如果你需要管理不同的功能或任务，可以使用分支进行修改：
```bash

### 1. **在本地 Python 项目中集成 Gemini API**

#### 步骤 1：安装所需依赖

1. 首先，你需要安装 **Google Generative AI SDK**（`google-genai`）：
   ```bash
   pip install google-genai
   ```

#### 步骤 2：设置 API Key

1. 在你的代码中配置 API Key，通常可以通过环境变量进行配置：
   ```bash
   export GEMINI_API_KEY="你的API_KEY"
   ```

   或者你也可以在代码中直接设置：
   ```python
   import google.generativeai as genai
   genai.configure(api_key="你的API_KEY")
   ```

#### 步骤 3：调用 Gemini API

1. 在你的项目中，调用 Gemini 模型并进行内容生成：
   ```python
   model = genai.GenerativeModel("gemini-1.5-pro-latest")
   response = model.generate_content("帮我写一篇关于气候变化的文章")
   print(response.text)
   ```

#### 步骤 4：修改本地项目的功能

1. 根据你的需求，你可以修改项目中调用 API 的部分。例如：
   - 你可以更改生成的内容类型（文本、代码、回答等）。
   - 添加对用户输入的处理，比如从 Web 界面或文件中读取内容并通过 Gemini API 生成响应。
   - 集成更多的功能，如自动化脚本、实时数据抓取、个性化推荐等。

### 2. **在本地 Web 项目中集成 Gemini API**

如果你在本地开发 Web 应用，可以通过后端调用 Gemini API，然后将结果展示给前端。

#### 步骤 1：安装必要的依赖

如果你使用的是 Node.js 环境，可以使用 `axios` 或其他 HTTP 请求库来调用 Gemini API。

```bash
npm install axios
```

#### 步骤 2：后端代码修改

在你的后端（如 Express.js）中，修改路由以集成 Gemini API：
```javascript
const axios = require('axios');

app.post('/generate-content', async (req, res) => {
    const userInput = req.body.input;  // 从前端获取用户输入

    try {
        const response = await axios.post('https://generativeai.googleapis.com/v1beta3/models/gemini-1.5-pro-latest:generateText', {
            prompt: userInput,
            apiKey: process.env.GEMINI_API_KEY,
        });
        res.json({ result: response.data });
    } catch (error) {
        res.status(500).send('Error generating content');
    }
});
```

#### 步骤 3：前端代码修改

在前端，你可以使用 JavaScript 或前端框架（如 React）发送请求并显示结果。

```javascript
async function generateContent(inputText) {
    const response = await fetch('/generate-content', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ input: inputText })
    });
    const data = await response.json();
    console.log(data.result);
    // 你可以在页面上显示生成的内容
}
```

#### 步骤 4：修改 UI 和功能

根据实际需求，你可以修改前端页面，允许用户输入不同的内容类型或交互方式，生成不同种类的文本、代码等。

### 3. **在命令行工具中集成 Gemini**

如果你在开发一个命令行工具，并希望集成 Gemini API，可以按以下步骤操作。

#### 步骤 1：安装所需依赖

```bash
npm install axios
```

#### 步骤 2：集成 API 调用

在你的命令行工具的代码中，调用 Gemini API 获取内容并显示在终端：

```javascript
const axios = require('axios');

async function generateContent(inputText) {
    try {
        const response = await axios.post('https://generativeai.googleapis.com/v1beta3/models/gemini-1.5-pro-latest:generateText', {
            prompt: inputText,
            apiKey: process.env.GEMINI_API_KEY,
        });
        console.log(response.data.result);
    } catch (error) {
        console.error('Error generating content:', error);
    }
}

// 使用用户输入的文本来调用该函数
const inputText = process.argv[2] || 'Hello, Gemini!';
generateContent(inputText);
```

#### 步骤 3：运行命令行工具

在命令行中运行：
```bash
node generate.js "Write a story about a futuristic world"
```

- **语音/视频答题**：用户通过语音或视频作答问题。
- **AI评分**：系统基于参考答案对用户答案进行自动评分，并给出反馈。
- **成绩展示与分享**：根据用户回答的成绩生成报告，支持分享功能。

## 2. 核心点

### 2.1 前端实现（微信小程序）

1. **界面设计**：

- **易错点**：在用户设备上获取音频/视频权限时，可能由于用户没有授权或权限请求失败导致功能不可用。
- **解决方案**：使用 `wx.authorize()` API获取权限，并在未授权时引导用户手动开启权限。始终提供友好的错误提示，告知用户开启权限的步骤。

### 3.2 API请求超时

### 3.3 AI评分误差

- **易错点**：AI评分可能因为用户的回答不完全匹配参考答案而给出较低分数，导致评分不准确。

### 3.4 视频文件上传大小问题

- **易错点**：微信小程序对上传文件的大小有一定限制，可能导致视频文件上传失败。
- **解决方案**：前端可以对视频文件进行压缩处理（如降低分辨率），确保文件不超过上传限制。同时，后端应检查文件大小并提供相应的反馈。

### 3.5 数据同步问题

- **易错点**：前后端在数据同步过程中可能出现延迟，导致用户界面反馈不及时。

> **Nano 插上 USB 后：板上电源 LED（红/绿灯）灭，电脑也认不到板子 → 说明 5 V 供电线被**  
> - **短路**（瞬间拉到 0 V，USB 过流保护触发）  
> - **或烧断**（板上自恢复保险丝 / 保护二极管熔掉）

---

## 一步步自检

| 步骤 | 该怎么量 / 看 | 可能结论 |
|---|---|---|
| **1 . 拔掉激光，只插 Nano** | USB 插电脑，LED 恢复亮 → **激光接反或短路**；<br>LED 仍不亮 → 看 2 |  |
| **2 . 测 5 V** | 用万用表⟵ 5 V ↔ GND：<br>• 有 5 V → LED 坏 / 串电阻烧；<br>• 0 V → 板上 **PTC 保险丝 (F1)** 熔断或 **TVS 二极管 D1** 短路 |  |
| **3 . 换另一 USB 口 / 充电头** | 若另一口能亮，原口触发过流保护，拔掉 5-10 min 会恢复 |  |
| **4 . 保险丝复位** | 把 Nano 静置 5 min→再插；若仍 0 V，多半 **D1** 烧短，需要剪掉或换板 |  |

## 为什么会拉短？

| 常见原因 | 防范 |
|----------|------|
| **红黑线接反** | 红 → 5 V、黑 → GND；任何一次试线前先断电确认颜色 |
| **激光模组内部焊点松脱** | 摇一摇听内部响声＝短路风险；先测阻值：红-黑间阻值 ≥ 60 Ω 才上电 |
| **激光规格其实是 3 V** | 3 V 模组直接上 5 V 会击穿；先限流 100 Ω 或用 3.3 V Pin 测试 |

> 你拍的详情页写 **“电压: 3 V，电流: <20 mA”** —— 说明这批模组预设 3 V 工作。  
> **直接 5 V 供电** 可能击穿管芯，导致大电流 → Nano 保险丝断、USB 过流。

---

## 正确的安全接法

### 方案 A（最保险）——先串 **150 Ω 电阻** 再上 5 V
```
Nano 5V ─┬─┬─> 红线
          │ 150Ω
          └─/\/\/─┘
Nano GND ─────────> 黑线
```
- 5 V 时电流 ≈ (5 V-2.7 V)/150 Ω ≈ 15 mA，绝不会烧板。  
- 线光稍暗但足以测试；确认没短路再换 100 Ω 或直接 5 V。

### 方案 B —— 用 **Nano 的 3.3 V Pin**
- CH340 Nano 自带 3.3 V LDO，可供 50–100 mA。  
- 红线接 3.3 V，黑线接 GND，不用额外电阻。

> 若只有旧 Nano（无 3.3 V Pin），可以把 **两节 1.5 V AA 并联** → 3 V 直接点亮。

## 修板 or 换板？

| 结果 | 处理 |
|------|------|
| 保险丝 F1 复位后 LED 恢复 | 问题解决；按上面限流接线 |
| D1 (USB “LC5306” TVS) 短路 | 用烙铁移除 D1，USB 5 V 恢复；板功能不受影响，少一层浪涌保护 |
| 板彻底无 5 V、电脑端提示“设备耗电过多” | 直接换新 Nano（￥12）最快 |

## 3 ️⃣ 如果万用表一测 5 V 立刻掉到 0 V（你说“吸了完了”）

**大概率是**：红黑表笔短接时触发了 USB 过流保护，USB 口会瞬间断电。  
- 拔掉板子，等待 30 秒再插；多数电脑 / 充电宝会自动复位。  
- 若反复插拔仍无 5 V，则可能板子 F1 保险丝永久熔断或 TVS 短路，需要更换板子或元件。

---

## 4 ️⃣ LED 直接“测发光电压”不可行

- LED 的亮度随电流（而不是电压）变化——相同电压下，不同颜色/批次亮度不同，无法精确判电压。  
- 真要测 “LED 点亮所需电压” 只能用可调电源 + 系列电阻 + 电流表，和这里判断 5 V 存在没关系。

2. **确认 5 V 正常后** 再用上面 **LED+电阻** 做亮灭指示。  
3. **之后给激光供电**

### 先帮你还原「一插表笔 → 板子 LED 熄灭」到底发生了什么

| 情况 | 为什么会熄灭 | 典型表现 |
|------|--------------|----------|
| **① 万用表转到了 mA／A 电流档** | 表笔内部被短接成 “一根导线”，等于直接把 **5 V 和 GND 短路** → USB 口进入过流保护，板上 PTC 保险丝 F1 也断流 | 电脑 USB 口瞬间掉电；Nano 电源灯灭；拔掉再插过几秒才恢复 |

## 如何确认板子是否真的“烧坏”还是 USB 过流保护

1. **把万用表转回 **V** 档（20 V 直流），红黑表笔分别插 **5 V** 与 **GND**。  
2. **拔掉板子 30 秒 → 重新插 USB**  
   - **出现 4.8–5.1 V** → 板子好的，只是上次短路触发过流；正常可继续用。

## 如果一直 0 V，怎么救？

| 元件 | 位置 | 排除 / 修复 |
|------|------|------------|
| **PTC 保险丝 F1** | Nano USB 口旁黄色贴片 (标“MF–”或空白) | 用 5 V 1 A 供电烧断→ 冷却 1–2 分钟通常自恢复；<br>若仍 0 V，可临时短接保险丝两端（⚠️ 失去保护） |
| **TVS 二极管 D1** | USB 口近端小黑芯片 (印“LC5306”或无印) | 若烧短会把 5 V 拉到 0 V；剪掉/烙铁移除后再测；若恢复 5 V 说明 D1 坏，其余 OK |

> 一整块 Nano 兼容板新的也就 **￥12–15**，如果测试发现 F1、D1 修复仍无 5 V，就直接换板最省时间。

4. 测完立即拔表笔，不要让两针同时碰到别的脚

| 现象 | 处理办法 |
|------|---------|
| Cursor 提示 `Client closed` | 把 `@latest` 去掉，只保留 `@browsermcp/mcp` 再刷新；或重启 MCP server。citeturn11view0 |
| 插件已安装但一直 “Not connected” | ① 确认浏览器标签页点击过 **Connect**；② 保证只开 **一个 DevTools panel**，多开会抢占端口。citeturn12view0 |
| `npx @browsermcp/mcp@latest --port 4891` 报 `unknown option --port` | 官方版走 **stdio**，不需要手动指定端口；若你想用 BrowserTools，使用上面双进程写法。 |
| Cursor 侧工具栏显示 “0 tools enabled” | 说明服务器没跑起来：在 Settings → MCP 查看进程日志，确认 Node 版本 ≥ 18，并能正常执行 `npx`。 |

## 5 在插件里新增你自己的功能（可选）

1. **manifest** 里声明一个 `chrome.devtools_page` 或 `chrome.action` 脚本。  
2. 在脚本里通过 `window.addEventListener('message', …)` 或 `chrome.runtime.onMessage` 暴露 API。  
3. 在 MCP Server 里新增一个 `tools.ts`，包装成 MCP “tool” 导出。  
4. 重新 `npn run dev`，再点插件上的 **Reload**。

这样你就可以在 Cursor 里直接输入：  

```
runMyTool { "selector": "#btn", "text": "点击一下" }
```

插件代码收到消息后执行 DOM 操作，最后把结果通过 MCP 回传给 Cursor，形成闭环。

### 一句话总结

> **关键是三步：插件 Connect → Cursor Settings 添加 `npx @browsermcp/mcp` → 聊天窗口发指令。**  
> 打通后，Cursor 就能把每一句自然语言翻译成插件里的 JavaScript 自动化动作，Chrome 页面动起来，你的开发/调试效率直接翻倍。
