#### prepareClaimForOrder({ orderId, userId })

- 查订单是否存在、是否属于当前用户；
- 看是否已经有绑定这个订单的 claim：
  - 有 → 直接复用，返回 `{ claimId, claimToken, orderId }`；

    - `id = uuid()`
    - `token = uuid()`
    - `status = 'PENDING_VERIFY'`

#### verifyClaimAndCaptureEvidence({ claimId?, orderId?, orderRef, userId })

- 用 `claimId` 或 `orderId` 找到对应 claim 和 order：
  - 找不到 → `CLAIM_NOT_FOUND` / `ORDER_NOT_FOUND`；
  - 用户不匹配 → `ORDER_FORBIDDEN`。
- **不再从 body 里拿 symbol / exchange / apiKey**，全部内部决定：
  - 默认交易所：`CLAIM_DEFAULT_EXCHANGE`（没设就用 `okx`）；
  - 默认交易对：`CLAIM_DEFAULT_SYMBOL`（没设就用 `BTC-USDT-SWAP`）；

- 根据模式选择验证来源：
  - `JP_VERIFY_TEST_MODE=1` → 返回固定 Demo 证据，方便前端调样式；
  - `USE_JP_VERIFY=1` → 调日本服务器 `jp-verify`；
  - 否则 → 用你本地直连 OKX 的实现（示例里叫 `fetchOkxEvidenceViaApiService`）。

在你本机开终端（不是服务器），在 `JWT` 换成你浏览器里现有的那个（从 Application → Local Storage 里拿），执行：

```bash
curl -i \
  -H "Authorization: Bearer <你的 JWT>" \
  -H "Content-Type: application/json" \
  -d '{"orderId":"<你前端卡片传的那个 order.id>"}' \
  http://127.0.0.1:3002/api/v1/claims/prepare
```

看返回：

- 如果是 `4xx`（比如 404 / 403），说明 **业务条件没满足**：
  - `ORDER_NOT_FOUND` → 你传的 orderId 后端根本查不到；
  - `ORDER_FORBIDDEN` → 订单不属于当前登录钱包用户。

- 如果是 `5xx`，堆栈会跟终端一样，多半是：
  - DB 没迁移（表不存在）；
  - 我们新写的 `claimsService` 里调用了 `db.orders`，但你的项目还没这个封装；
  - 之类的纯代码错误。

```ts
export async function runOrderVerifyWithStoredApi(
  input: RunOrderVerifyInput,
): Promise<RunOrderVerifyResult> {
  const { userId, orderId, ordRef, pair } = input;

  if (order.userId !== userId) {
    throw new HttpError(403, "ORDER_FORBIDDEN", "该订单不属于当前用户");
  }

  // 2）读取用户最新的 OKX API Key
  const apiKeyRow = await findLatestOkxApiKeyByUserId(userId);
  if (!apiKeyRow) {
    throw new HttpError(
      400,
      "OKX_API_MISSING",
      "当前账号未配置 OKX API，请先在 API 设置页面填写",
    );
  }

  const decrypted = ApiKeyEncryptionService.decryptApiKey(apiKeyRow.payload);
  const { apiKey, secretKey, passphrase } = decrypted;

  if (!apiKey || !secretKey || !passphrase) {
    throw new HttpError(
      500,
      "OKX_API_INVALID",
      "OKX API 配置不完整，请重新保存",
    );
  }

  // 3）交易对映射：只支持 btcusdt / btcusdc

  // 4）调用 jp-verify 标准验证接口
  const url = `${JP_VERIFY_BASE}/verify/standard`;

  const jpReqBody = {
    exchange: "okx",
    keyMode: "inline",
    apiKey,
    secretKey,
    passphrase,
    ordId: ordRef,
    instId,
  };

  const jpRes = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(jpReqBody),
  });

    const text = await jpRes.text().catch(() => "");
    throw new HttpError(
      502,
      "JP_VERIFY_FAILED",
      `jp-verify 请求失败: ${jpRes.status} ${jpRes.statusText} ${text}`,
    );
  }

  const data = (await jpRes.json()) as any;

  // 这里按 jp-verify 的返回结构取字段

  const verifyStatus = data.verifyStatus ?? (isLiquidated ? "PASS" : "FAIL");

    instId,

  };
}
```

## 1. 规则先定死：钱包 = 唯一身份

```ts
import { requireJwtAuth } from "../middleware/enhancedAuth";
import { runOrderVerifyWithStoredApi } from "../services/claimsVerifySimpleService";

const router = express.Router();

const schema = z.object({
  orderId: z.string().min(1, "orderId 不能为空"),
  ordRef: z.string().min(1, "ordRef 不能为空"),

// POST /api/v1/claims/verify-by-order
router.post("/verify-by-order", requireJwtAuth, async (req, res, next) => {
  try {
    const { orderId, ordRef, pair } = schema.parse(req.body);
    const wallet = req.user!.walletAddress;

    const result = await runOrderVerifyWithStoredApi({
      wallet,
      orderId,
      ordRef,

export default router;
```

```ts
          ok: false,
          code: "JP_VERIFY_BASE_URL_MISSING",
          message: "JP_VERIFY_BASE_URL not configured",
        });

      const apiKey = process.env.JP_VERIFY_API_KEY;

      const jpResp = await axios.post(
        `${baseUrl}/api/v1/verify/by-order`,
        {
          orderRef,
          walletAddress,
        },

          headers: apiKey

          timeout: 10_000,
```

### 步骤 1：看 us-backend 的日志

> 小规则：
> - 出现 `ECONNREFUSED` → 说明 jp-verify 根本没跑起来 / 端口不对  
> - 出现 `ENOTFOUND` → `JP_VERIFY_BASE_URL` 域名写错  
> - 出现 4xx/5xx 响应 → 是 jp-verify 收到请求后主动报错（body/data 问题）

```bash
  }'
```

- 直接 `Connection refused` → jp-verify 没跑 / 端口错

```json
}
```

你就能自己判断：
