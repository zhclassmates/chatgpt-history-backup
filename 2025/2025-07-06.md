### 针对 Apple M4 的简化操作指南

Apple M4 芯片不支持 NVIDIA CUDA，因此我们将使用 CPU 或 Apple Silicon 的 MPS（Metal Performance Shaders）后端运行 RVC。以下是具体步骤：

1. **准备环境**：
   - 确保 macOS 已更新（建议 macOS Ventura 或更高版本）。
   - 安装 Homebrew（macOS 的包管理器）：
     ```bash
     /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
     ```
   - 安装 Python 3.8–3.10（M4 兼容）：
     ```bash
     brew install python@3.10
     ```
   - 安装 Git：
     ```bash
     brew install git
     ```

2. **克隆项目**：
   ```bash
   git clone https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI.git
   cd Retrieval-based-Voice-Conversion-WebUI
   ```

3. **安装依赖**：
   - 安装 PyTorch（Apple Silicon 优化版）：
     ```bash
     pip3 install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
     ```
     **说明**：Apple M4 支持 MPS 加速，但 RVC 项目可能未完全适配 MPS。如果遇到性能问题，建议使用 CPU 模式。
   - 安装核心依赖（精简版）：
     ```bash
     pip3 install -r requirements.txt
     ```
     如果 `requirements.txt` 中某些库（如 `onnxruntime-gpu`）不兼容 M4，可以手动安装以下核心库：
     ```bash
     pip3 install gradio librosa numpy scipy fairseq onnxruntime
     ```

4. **安装 FFmpeg**：
   ```bash
   brew install ffmpeg
   ```

5. **下载预训练模型**：
   - 从 [Hugging Face](https://huggingface.co/lj1995/VoiceConversionWebUI/tree/main/) 下载以下文件，放入项目对应目录：
     - `./assets/hubert/hubert_base.pt`
     - `./assets/pretrained` 文件夹
     - `./assets/uvr5_weights` 文件夹
     - `./rmvpe.pt`（音高提取模型）
   - 建议手动下载并放置到正确路径，或者使用项目 `tools` 文件夹中的下载脚本（如果可用）。

6. **启动 WebUI**：
   - 使用项目提供的 `run.sh` 脚本：
     ```bash
     sh ./run.sh
     ```
     这会自动安装依赖并启动 WebUI。如果失败，可以手动启动：
     ```bash
     python3 infer-web.py
     ```
   - 浏览器会打开 `http://127.0.0.1:7860`，你可以通过界面上传音频、选择模型并进行变声。

7. **使用建议**：
   - **训练**：上传 10 分钟以上低噪语音数据，通过 WebUI 训练界面配置参数。
   - **推理**：加载模型，上传音频，调整音高生成结果。
   - **实时变声**：运行 `go-realtime-gui.bat`（需检查 macOS 兼容性，可能需要额外配置音频设备）。

**注意**：
- Apple M4 的性能强大，但 RVC 的部分组件（如 RMVPE 音高提取）可能未针对 MPS 优化，运行速度可能较慢。
- 如果遇到依赖冲突，尝试使用 Python 3.9（更稳定）或逐一安装核心库。
- 实时变声可能因延迟较高而不理想，建议优先使用训练和推理功能。

### 用 Time Machine 做一次“整机镜像”——详细步骤与避坑清单  
（macOS Sonoma 〜 Sequoia 皆通用）

---

#### 0 . 准备外接硬盘  
| 需求 | 最低规格 | 建议做法 |
|------|----------|----------|
| 容量 | **≥ 系统盘已用空间 × 1.5** | 1 TB 以上，USB-C/Thunderbolt SSD 更快 |
| 文件系统 | APFS 或 HFS+（Time Machine 会自动格式化） | 接上后在「磁盘工具」点**抹掉 › 格式：APFS › 用作备份磁盘** |
| 加密 | **强烈建议**启用 | 备份开始时勾选「加密备份」，输入独立密码 |

---

#### 1 . 首次完整备份（最好插电，保持盖开）  

1. **系统设置 › 通用 › Time Machine** → 选「添加备份磁盘」→ 选你的硬盘。  
2. 勾选「立即开始备份」。第一次会花最长时间（USB SSD≈150 GB/小时）。  
3. 备份完成后，Time Machine 每小时增量一次，自动维护 APFS **本地快照**，即使硬盘拔掉也能回溯单个文件。citeturn0search1  

> ***校验备份***：备份完成后，点 Time Machine 图标 →「进入 Time Machine」，随便恢复一张桌面图片测试可否成功复制。

---

#### 2 . 抹盘 & 重装 macOS  

1. **关机 → 长按⏻ / Touch ID** 进入**恢复模式**。  
2. 在「磁盘工具」里选系统盘卷宗（通常叫 *Macintosh HD*），点「抹掉」，格式保持 APFS。  
3. 关掉磁盘工具 → 选「重新安装 macOS Sonoma/Sequoia」，跟随向导完成联网安装。  

---

#### 3 . 用「迁移助理」从 Time Machine 恢复  

重装完成后首次开机的「**设置助理**」会问：  
> *要把信息从哪里转移？*  

选「**从 Time Machine 备份**」，插上备份盘，按步骤：citeturn0search0turn0search4  

| 步骤 | 关键选项 | 建议 |
|------|----------|------|
| 选择备份盘 | 选最新完整备份（日期+时间） | 如果做过多次，注意别选错 |
| 选择传输内容 | **用户帐号**、**应用程序**、**系统与网络设置** | 若想干净些，可取消“系统文件和网络设置” |
| 账号密码 | 迁移助理会提示创建/合并用户 | 选“用同名帐号合并”可带回钥匙串—钱包扩展直接能解密 |

> ⚠ **浏览器高级检查**  
> - 完成迁移后，打开 Chrome/Brave 检查扩展 & 钱包可否直接解锁；  
> - 真的打不开时，用你事先抄下的助记词「导入钱包」即可。

---

#### 4 . 仅恢复局部数据的方法  

若你后来想**只取回某个文件夹 / 单个应用设置**：  
1. 插上备份盘，点菜单栏的 Time Machine 图标 →「进入 Time Machine」。  
2. Finder 窗口会穿梭到历史版本，选目标文件夹 →「恢复」。  
   - 例如 `~/Library/Application Support/Google/Chrome/Default`。  
3. 恢复前同一位置若已有同名文件，系统会提示保留两份或替换。

---

#### 5 . 常见疑问 & 故障排查  

| 现象 | 解决思路 |
|------|----------|
| **迁移助理识别不到备份盘** | 确认硬盘在 Finder 可见；若是新款 Mac 且硬盘走 USB-A 桥接，换 C-to-C 线或自带供电 HUB。 |
| **提示“备份已损坏”** | 在旧系统 `tmutil verifychecksums /Volumes/Backup` 检测；如果只有增量损坏，可删最近一次增量后重试。 |
| **恢复后磁盘空间紧张** | 迁移助理把旧用户文件夹搬回来了，可手动把不再需要的大型素材、虚拟机镜像移出或外接盘保存。 |
| **要保 Wallet 又怕泄露助记词** | Time Machine 备份已加密 + 本机 FileVault，理论安全；但最佳实践仍是把助记词离线存放（纸/硬件密码本），恢复后立即验证余额无误再销毁纸条。 |

---

#### 一句话总结  
> **Time Machine + 迁移助理** = 官方“整机镜像”方案，**最稳最省事**；备份盘插上、电源不断，一顿午饭功夫就能把浏览器、钱包和所有细枝末节原样搬回新系统。  

搞定后，记得把备份盘拔掉妥善保管或加锁，别让助记词与电脑同时丢失。祝重装顺利！

但「一模一样」也有前提和例外，下面把关键点列清楚，保证你知道哪些会 100% 带回来，哪些可能还要额外动作。

| 组件 | 复制资料夹后能否直接恢复？ | 可能需要额外操作 / 会失效的情况 |
|------|---------------------------|--------------------------------|
| **书签、历史、站点设置、扩展本体** | ✅ 一般都 OK | 如果重装后浏览器升级跨度很大，个别旧扩展版本可能与新内核不兼容，需要手动更新 |
| **Cookies / 登录状态** | ✅ 大多可用 | 某些网站会在检测到硬件变动或 IP 变化后强制重新登录（尤其是网银、Google、Facebook 等） |
| **保存的用户名/密码** | ⚠ **取决于 Keychain** | Chrome/Brave/Edge 会用 macOS 钥匙串对密码再加一层锁：<br>• 如果你在迁移助理里「合并同名用户」，旧钥匙串也跟着过来 → 直接解锁<br>• 如果只拷文件夹而没带钥匙串，新系统第一次读取时会弹窗要你输入**旧系统的登录密码**；输对后即可解锁<br>• 若连旧密码都忘了，只能靠浏览器同步或手动导出 CSV |
| **加密钱包扩展 (MetaMask / Rabby / Phantom…)** | ⚠ 99% 需要**重新输入助记词/密码** | 钱包私钥是用你当时设的「钱包密码」加密后存进浏览器文件 + 钥匙串<br>拷文件能保留数据，但新系统首次打开会要求输入「钱包密码」或直接让你用助记词重新导入——所以**助记词一定要在手** |
| **扩展的本地数据库 (如 Tampermonkey 脚本、uBlock 规则)** | ✅ 会随 `IndexedDB` 等文件一起搬走 | 个别扩展在版本更新后数据库 schema 变了，首次打开可能自动迁移或重建 |
| **下载记录、最近标签页、会话恢复** | ✅  | 只要完整文件夹都在，就能恢复上次关闭的全部窗口 |
| **Widevine DRM 组件** | ✅ / �� | 浏览器会在后台自检兼容性，必要时自动重装组件；极少数旧版 Chrome Profile 拿到新系统后需首次播放 Netflix 时下载 |
| **系统级证书、企业代理配置** | ❌ | 这些在「钥匙串访问」→「系统」里，不在浏览器资料夹；需用 Time Machine 迁移，或手动导出 `.p12` / `.mobileconfig` 再导入 |

### 操作细节 & 常见坑

1. **只拷「Profile」文件夹，不必拷 Cache**  
   - 路径示例：`~/Library/Application Support/Google/Chrome/`  
   - 里面 `Default`、`Profile 1`… 开头的文件夹是核心；`Cache`、`ShaderCache` 体积大又可自动重建，可省略。  

2. **版本匹配**  
   - 最保险：在旧系统里看一下 “About Chrome/Brave” 的版本号，重装后先下载相同或更高的小版本再粘资料夹。  
   - 若差距太大（例如从 Chrome 99 跳到 126），扩展 API 有变化，个别旧扩展可能崩溃，需要升级扩展或删掉对应目录。  

3. **Keychain 解锁弹窗**  
   - 第一次启动 Chrome/Brave 时，macOS 可能弹「Chromium 想要使用您的机密信息」——输入**旧系统登录密码**即可把旧 Keychain 解密并迁走。  
   - 若你选择全新 Keychain（或输错多次导致拒绝），浏览器里的保存密码会显示空白，需要靠同步或 CSV 重新导入。  

4. **钱包扩展**  
   - 文件还在，但通常会要求输入“钱包密码”或助记词才加载账户；如果你忘记了钱包密码，就只能**用助记词重新导入**。  
   - 部分扩展（如 Rabby）在检测到环境变化后，会提示“需要重新加密存储”，属于正常流程。  

5. **关闭自动登陆同步**（可选）  
   - 若你就是为了离线保存整个配置，可在新系统第 一次启动浏览器之前断网，确保不会被云端同步覆盖；确认一切就绪再连网。  

6. **保险操作：迁移前先做验证**  
   - 在旧系统里建一个 *临时用户*，把拷好的资料夹粘进去，确认能正常启动浏览器、钱包能解锁，再重装系统。  

### 总结一句话  
> **拷整段浏览器用户资料夹 + 备份助记词/旧 Keychain** → 重装后按原位覆盖 → 除了少数需要二次登录的网站和必须输入助记词的钱包，其余浏览体验、扩展设置、脚本文档都能 100% 恢复。  

这样做比 Time Machine 还“干净”，只要你能接受：  
- 某些敏感站点会让你重新验证登录；  
- 钱包一定要手动输入助记词/密码才能解锁。  

确认这些都不成问题，就可以放心使用「拷文件夹 → 覆盖」的轻量方案。祝迁移顺利！

下面是一份 **完整可直接复制的 Python 脚本**（保存为 `verify_backup.py` 即可）。  
它做的事情：

1. 递归扫描 **源目录** 和 **目标目录（外置硬盘）**。  
2. 按相对路径逐一比对：  
   - 是否都存在  
   - 文件大小是否一致  
   - （可选）SHA-256 哈希是否一致  
3. 用 ✓ / ✗ 打印结果，并生成 `verify_report.tsv` 供后续留档。  
4. 如果一切 OK，再加 `--delete-ok` 执行即可批量删除源目录中已成功验证的文件／文件夹。

> ⚠ **强烈建议先跑一次不带 `--delete-ok` 的干跑（dry-run）**，确认报告全为 ✓ 后再真正删除！

---

```python
#!/usr/bin/env python3
"""
verify_backup.py
~~~~~~~~~~~~~~~~
比较本机目录与外置硬盘备份目录的文件完整性。
- 默认按文件大小比对；加 --hash 才计算 SHA-256（慢，但最保险）。
- 支持在全部通过时自动删除源文件 (--delete-ok)。
"""

import argparse
import hashlib
import os
import shutil
import sys
from pathlib import Path
from typing import Dict, Tuple

CHECK = "✓"
CROSS = "✗"


def sha256sum(path: Path, block_size: int = 1 << 20) -> str:
    h = hashlib.sha256()
    with path.open("rb") as f:
        while chunk := f.read(block_size):
            h.update(chunk)
    return h.hexdigest()


def build_index(root: Path) -> Dict[str, Tuple[int, str]]:
    """
    返回 {相对路径: (文件大小, sha256 或 '')}
    相对路径统一用 posix 分隔符，便于跨平台比较。
    """
    index = {}
    for f in root.rglob("*"):
        if f.is_file():
            rel = f.relative_to(root).as_posix()
            size = f.stat().st_size
            index[rel] = (size, "")  # hash 稍后再算（可选）
    return index


def main():
    p = argparse.ArgumentParser(
        description="Compare two folders (source vs backup) to verify backup integrity."
    )
    p.add_argument("src", type=Path, help="源目录（Mac 本地）")
    p.add_argument("dst", type=Path, help="目标目录（外置硬盘备份）")
    p.add_argument(
        "--hash",
        action="store_true",
        help="同时比较 SHA-256；安全但会显著变慢",
    )
    p.add_argument(
        "--delete-ok",
        action="store_true",
        help="在全部文件验证通过后，删除源目录中对应文件/文件夹",
    )
    args = p.parse_args()

    src_root = args.src.expanduser().resolve()
    dst_root = args.dst.expanduser().resolve()

    if not src_root.is_dir() or not dst_root.is_dir():
        sys.exit("❌ 目录不存在，请检查路径！")

    print(f"🔍 Indexing {src_root} ...")
    src_index = build_index(src_root)
    print(f"🔍 Indexing {dst_root} ...")
    dst_index = build_index(dst_root)

    all_ok = True
    report_lines = ["status\tbytes\tpath"]

    for rel, (size_src, _) in src_index.items():
        if rel not in dst_index:
            print(f"{CROSS} 缺失于备份: {rel}")
            report_lines.append(f"missing\t{size_src}\t{rel}")
            all_ok = False
            continue

        size_dst, _ = dst_index[rel]
        if size_src != size_dst:
            print(f"{CROSS} 大小不符: {rel}")
            report_lines.append(f"size_mismatch\t{size_src}\t{rel}")
            all_ok = False
            continue

        # 可选哈希校验
        if args.hash:
            hash_src = sha256sum(src_root / rel)
            hash_dst = sha256sum(dst_root / rel)
            if hash_src != hash_dst:
                print(f"{CROSS} 哈希不符: {rel}")
                report_lines.append(f"hash_mismatch\t{size_src}\t{rel}")
                all_ok = False
                continue

        print(f"{CHECK} OK: {rel}")
        report_lines.append(f"ok\t{size_src}\t{rel}")

    # 反向检查：备份里有而源里没有的文件
    for rel in dst_index.keys() - src_index.keys():
        size, _ = dst_index[rel]
        print(f"⚠ 备份多余文件: {rel}")
        report_lines.append(f"extra_in_backup\t{size}\t{rel}")
        # 不算失败，留给用户自己决定是否清理

    # 写报告
    report_path = Path("verify_report.tsv")
    report_path.write_text("\n".join(report_lines), encoding="utf-8")
    print(f"\n📄 已生成报告: {report_path.resolve()}")

    # 全通过且要求删除
    if all_ok and args.delete_ok:
        confirm = input(
            "✅ 全部文件验证通过。确定删除源目录中的文件吗？ [yes/NO] "
        ).strip().lower()
        if confirm == "yes":
            print("🚮 正在删除 ...")
            for rel in src_index:
                try:
                    (src_root / rel).unlink()
                except IsADirectoryError:
                    # 等文件删完后再删空目录
                    pass
            # 把空目录从深到浅删除
            for d in sorted(src_root.rglob("*"), key=lambda x: -len(x.parts)):
                if d.is_dir() and not any(d.iterdir()):
                    d.rmdir()
            print("🎉 删除完毕！")
        else:
            print("操作已取消，未删除任何文件。")
    elif args.delete_ok and not all_ok:
        print("❌ 有文件未通过验证，已阻止删除。先检查报告。")


if __name__ == "__main__":
    main()
```

## 如何使用

```bash
# 1. 干跑（推荐先这样）
python3 verify_backup.py /Users/yourname/Documents /Volumes/BackupDrive/Documents

# 2. 加 --hash 做深度校验
python3 verify_backup.py /Users/yourname/Documents /Volumes/BackupDrive/Documents --hash

# 3. 全部通过后自动删除源文件（危险！）
python3 verify_backup.py /Users/yourname/Documents /Volumes/BackupDrive/Documents --hash --delete-ok
```

- **报告文件** `verify_report.tsv` 可用 Numbers / Excel 打开查看。  
- `status` 字段说明  
  - `ok`     → 完全一致  
  - `missing` → 备份缺失  
  - `size_mismatch` / `hash_mismatch` → 不一致  
  - `extra_in_backup` → 备份中多出的文件（可手动审查后决定是否删除）  

---

### 删除逻辑说明

- 仅在 **全部校验通过** **且** 你显式添加 `--delete-ok` 时才会触发删除；否则脚本绝不会修改任何源文件。  
- 删除流程先删文件，再自下而上删空目录，确保不误删未验证的其它内容。
