**Garry Tan 这种属于“多角色 Agent 工作流”这一支，而且是比较工程化、比较成熟的一支。** 他不是发明了所有 AI 的标准形态。gstack 本质上是给 Claude Code 加上一组结构化角色和流程，比如 CEO review、工程架构、设计、QA、发布等，把一个基础模型组织成“虚拟团队”。citeturn816322search1turn816322search0

现在市面上的 AI 大致可以分成 5 类：

1. **聊天型 AI**
   例如普通 ChatGPT、Claude 聊天。
   核心是：
   `你问 → AI答`
   
   它们本身不一定长期运行任务，也不天然形成团队。

2. **Copilot 型**
   例如 IDE 里的编程助手、文档助手。
   核心是：
   `你工作 → AI辅助`
   
   人还是主驾驶。

3. **单 Agent 型**
   给它目标后，它自己拆任务、调用工具、浏览网页、写代码。
   核心是：
   `目标 → 计划 → 执行 → 反馈`
   
   这已经开始接近“员工”。

4. **多 Agent / 多角色型**
   这就是 Garry Tan 的路线。
   
   一个模型或者多个模型分别扮演：
   `CEO → PM → 工程师 → Reviewer → QA → Release`
   
   重点不是模型数量，而是**职责分工 + 检查流程 + Skill + 状态传递**。gstack 就是这种结构。citeturn816322search6

5. **Agent OS / AI 公司型**
   这是更往前的一层：
   
   `长期目标`
   ↓
   `多个专业 Agent`
   ↓
   `共享记忆/数据库`
   ↓
   `自动任务`
   ↓
   `现实工具`
   ↓
   `结果反馈`
   ↓
   `继续运行`
   
   这里 AI 不只是“角色扮演”，而是开始形成真正的持续工作系统。
