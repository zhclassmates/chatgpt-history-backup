## 概览  
将本地文件上传到 Google Drive，既可以使用最简单的 **网页端操作**，也能借助 **桌面客户端** 实现自动同步，或通过 **API/脚本** 完成批量、自动化上传。以下内容分为三大部分：  
1. **Web 界面上传**（适合少量文件或临时使用）  
2. **Drive for Desktop**（适合持续同步，像本地文件夹一样管理）  
3. **API 或脚本上传**（适合批量或集成到工作流中）  

---

## 一、通过 Web 界面上传

1. 打开浏览器，访问 https://drive.google.com citeturn0search0。  
2. 点击左上角的 **“新建” → “文件上传”**（或“文件夹上传”）citeturn0search6。  
3. 在弹出的文件选择对话框中，选中本地文件（或文件夹），点击“打开”开始上传。  
4. 上传完成后，可在 **“我的云端硬盘”** 中看到刚刚上传的文件。  

> **Tip**：支持把文件直接拖拽到网页中，浏览器会自动启动上传任务。

## 二、使用 Drive for Desktop（原 Backup & Sync）  

### 1. 安装与登录  
- Windows/macOS 用户可从官方页面下载安装包：  
  https://support.google.com/drive/answer/7329379 citeturn0search1  
- 安装完成后运行程序并登录 Google 账号。  

### 2. 同步设置  
- 在应用设置中，勾选要 **同步到云端的本地文件夹**（可多选）citeturn0search1。  
- 也可勾选“将云端 Drive 文件夹同步到此电脑”，在本地会生成一个 **“Google Drive”** 目录，像操作普通文件夹一样读写。  

### 3. 自动上传  
- **任何复制到已同步文件夹** 的本地文件，都会被后台自动上传到云端，**无需额外操作**。  
- 变动会实时同步：新增／修改／删除都能反映在 Google Drive 上。

## 三、通过 API/脚本自动化上传

### 1. 简易 Python 示例（Drive API v3）  
```python
from google.oauth2 import service_account
from googleapiclient.discovery import build
from googleapiclient.http import MediaFileUpload

# 1) 准备服务账号凭证 JSON
creds = service_account.Credentials.from_service_account_file('service_account.json',
        scopes=['https://www.googleapis.com/auth/drive.file'])

service = build('drive', 'v3', credentials=creds)

# 2) 要上传的本地文件路径与元数据
file_metadata = {'name': 'example.txt'}
media = MediaFileUpload('local/path/to/example.txt', mimetype='text/plain')

# 3) 调用 API 创建文件
file = service.files().create(body=file_metadata, media_body=media, fields='id').execute()
print(f"Uploaded File ID: {file.get('id')}")
```  
> **参考**：Google Drive API 文档 citeturn0search2

### 2. 批量脚本示例

```python
import os, glob
from google.oauth2 import service_account
from googleapiclient.discovery import build
from googleapiclient.http import MediaFileUpload

# 初始化 Drive 服务
creds = service_account.Credentials.from_service_account_file(
    'service_account.json',
    scopes=['https://www.googleapis.com/auth/drive.file'])
service = build('drive', 'v3', credentials=creds)

# 扫描本地文件夹
for filepath in glob.glob('to_upload/*'):
    fname = os.path.basename(filepath)
    media = MediaFileUpload(filepath, resumable=True)
    file = service.files().create(body={'name': fname}, media_body=media).execute()
    print(f"Uploaded {fname} → ID {file['id']}")
```

Below is a quick guide to creating and using a Kubernetes ConfigMap, whether you need to inject configuration files or environment variables into your Pods.

## 1. Create a ConfigMap

### a. From literal key/value pairs  
```bash
kubectl create configmap my-config \
  --from-literal=LOG_LEVEL=debug \
  --from-literal=API_ENDPOINT=https://api.example.com
```

### b. From files  
```bash
kubectl create configmap my-config \
  --from-file=app.properties \
  --from-file=db.conf
```

### c. From a directory  
All files in the directory will become entries in the ConfigMap (filename → file contents):
```bash
kubectl create configmap my-config \
  --from-file=./config-dir/
```

### d. Declaratively via YAML  
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-config
data:
  LOG_LEVEL: debug
  API_ENDPOINT: https://api.example.com
  app.properties: |
    feature.enabled=true
    timeout=30
```
Apply it with:
```bash
kubectl apply -f my-config.yaml
```

---

## 2. Consume a ConfigMap in a Pod

### a. As environment variables  
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-env
spec:
  containers:
  - name: app
    image: your-image
    envFrom:
    - configMapRef:
        name: my-config
```

### b. As individual env vars with custom names  
```yaml
    env:
    - name: LOG
      valueFrom:
        configMapKeyRef:
          name: my-config
          key: LOG_LEVEL
    - name: API_URL
      valueFrom:
        configMapKeyRef:
          name: my-config
          key: API_ENDPOINT
```

### c. As files in a volume mount  
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-volume
spec:
  containers:
  - name: app
    image: your-image
    volumeMounts:
    - name: cfg
      mountPath: /etc/config
  volumes:
  - name: cfg
    configMap:
      name: my-config
      # optional: only include specific keys
      # items:
      #   - key: app.properties
      #     path: app.properties
```
Inside the container, you’ll find `/etc/config/LOG_LEVEL`, `/etc/config/API_ENDPOINT`, or your files.

---

## 3. Updating a ConfigMap

1. Edit YAML or recreate with `kubectl create configmap --from-… --dry-run=client -o yaml | kubectl apply -f -`.  
2. Rolling update your Deployment/Pod to pick up changes:
   ```bash
   kubectl rollout restart deployment/your-deployment
   ```

---

## 4. Tips & Best Practices

- **Immutable ConfigMaps**: set `immutable: true` to prevent accidental edits.  
- **Versioning**: include a version label or annotation in the metadata to track changes.  
- **Limit size**: ConfigMaps are meant for small config—not large binary data.  
- **Security**: sensitive data should go into Secrets, not ConfigMaps.

With these steps, you can create, consume, update, and manage ConfigMaps effectively in your Kubernetes workloads.

## 一、准备 Google Drive 访问凭证

### 1. **创建书籍结构**
   - 在 Typora 中，使用 Markdown 语法来创建章节标题。
   - 比如：
     ```markdown
     # 第一章 标题

     ```

     ```markdown
     [TOC]
     ```
   - 这会根据标题层级自动生成一个导航目录，方便浏览和导出时的结构化显示。

       ```markdown
       | 表头1 | 表头2 |
       |-------|-------|
       ```

如何给终端赋予权限

### AI
<!-- mid: cb37fd73-5801-4da4-bd81-0a0f120eda9c -->
在终端中“赋予权限”通常是指让某个文件（尤其是脚本或可执行程序）拥有执行权限。这在使用 `.sh` 脚本、Python 文件或某些第三方工具时非常常见。

以下是常见系统下的操作方法：

---

### 🐧 macOS / Linux：使用 `chmod` 命令

#### ✅ 给文件赋予执行权限
```bash
chmod +x 文件名
```
比如：
```bash
chmod +x install.sh
```

#### ✅ 用管理员权限运行脚本
```bash
sudo ./文件名
```
比如：
```bash
sudo ./install.sh
```

---

### 💡 如果你是双击打不开脚本文件：

你可以：
```bash
cd 文件所在目录
chmod +x 文件名
./文件名
```

---

### 🪟 Windows（使用 Git Bash / WSL / CMD / PowerShell）

Windows 不使用 `chmod`，但你可以：

- 如果是 `.bat` 或 `.exe` 文件：直接双击运行或使用管理员权限运行；
- 如果是使用 Git Bash 或 WSL 的 Linux 脚本：可以同样使用 `chmod +x`；

#### 在 PowerShell 中以管理员权限运行脚本（例如 `.ps1`）：
首先确保你允许脚本执行：

```powershell
Set-ExecutionPolicy RemoteSigned
```

然后运行脚本：
```powershell
.\脚本名.ps1
```

---

### 检查当前权限
```bash
ls -l 文件名
```

输出示例：
```bash
-rwxr-xr--  1 user  staff  1234 Apr 30 12:34 script.sh
```
其中 `x` 表示有“执行（execute）”权限。

如何给mac. 终端赋予权限

在 macOS 中，如果你要给 **终端（Terminal）** 赋予某些权限（例如访问麦克风、摄像头、文件夹等），可以按照以下步骤操作：

---

### ✅ 一、赋予“终端”访问磁盘或文件夹的权限：

1. 打开 **系统设置**（System Settings）  
   - macOS Ventura 或更高版本：点击苹果菜单 → 系统设置
   - macOS Monterey 及更早版本：点击苹果菜单 → 系统偏好设置

2. 前往：**隐私与安全性（Privacy & Security）**  
   > macOS Monterey 及以前叫 “安全性与隐私（Security & Privacy）”

3. 在左侧找到并点击：
   - **“完全磁盘访问权限（Full Disk Access）”**
   - 或 **“文件与文件夹（Files and Folders）”**
   - 或 **“辅助功能（Accessibility）”**（如果你需要脚本控制终端）

4. 点击右下角的 **“+” 按钮** 添加 **终端** 应用：
   - 终端路径一般在 `/System/Applications/Utilities/Terminal.app`
   - 或者可以在“应用程序 > 实用工具”里找到 Terminal，然后拖进去

5. 添加完成后，**重启终端** 应用以生效。

---

### ✅ 二、赋予“终端”麦克风或摄像头权限（如果运行脚本时需要）：

同样在 **系统设置 → 隐私与安全性** 中：

- 选择 **麦克风** 或 **摄像头**
- 勾选/允许 “终端” 或你正在使用的终端程序（如 iTerm）

---

### ✅ 三、确保你正在运行的脚本也有权限

即使终端有权限，有时你运行的某些脚本、命令行工具（如 `ffmpeg`、`python`）也可能需要手动授权。

---

### ⛔️ 注意事项：

- **首次访问敏感资源时**，macOS 通常会弹窗询问是否授权终端访问，这时候点击 “允许” 即可。
- 对于 iTerm、Warp、Hyper 等第三方终端，也需单独赋予相同权限。
- 如果权限设置后仍无效，尝试**重启 Mac**。

在 macOS 中没有像 Windows 那样「右键以管理员身份运行终端」的操作方式，但你**可以通过以下方法在终端中获取管理员权限**：

---

### ✅ 方法一：使用 `sudo` 命令（标准方式）

`sudo`（Super User DO）是临时以管理员身份运行命令的方法。

```bash
sudo <你的命令>
```

**示例：**

```bash
sudo nano /etc/hosts
```

系统会提示你输入当前账户的密码（不会显示），输入后就以管理员权限执行该命令。

---

### ✅ 方法二：打开一个 root（管理员）终端 shell

如果你希望在终端中持续使用管理员权限，可以切换到 root 用户：

```bash
sudo -s
```

或者：

```bash
sudo su
```

输入密码后，你就会进入一个管理员 shell，提示符通常会变成 `#`，此时你可以直接运行多个需要管理员权限的命令。

要退出 root 模式，输入：

```bash
exit
```

---

### ⚙️ 补充说明

- 使用 `sudo` 需要你的账户具备管理员权限（系统默认第一个用户是管理员）。
- 如果你在 `sudo` 时收到 “用户不在 sudoers 文件中” 的错误，你可能不是管理员账户，需联系设备管理员。
