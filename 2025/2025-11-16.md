逻辑变成：

1. 用户在卡片里输入 `orderRef`，点「验证」；
2. `ensureWalletLogin()` 检查本地有没有 JWT：
   - 有：直接继续；
   - 没有：调起 `loginWithWallet()`，弹出小狐狸登录 + SIWE 签名，拿到 JWT 存到 localStorage；
3. 后面的 `authFetchJson` 调用自然就带上 `Authorization: Bearer <JWT>`，后端不再 401。

---

## 3 个小检查，确保 401 消失

改完之后，可以按这个顺序确认一下：

### 检查 1：浏览器里是否有 token

在浏览器 DevTools 里：

- 打开 Application → Local Storage → `http://localhost:3000`；
- 看有没有你存 JWT 的那个 key（和 `authFetch.ts` 一致），里面有一串长长的 token。

如果没有：

- 说明 `loginWithWallet()` 没有正确把 token 写入 localStorage；
- 去 `auth.ts` 里看它在 `/auth/siwe/verify` 成功之后具体是怎么存的，把 key 名记下来，和 `authFetch.ts` & `hasJwt()` 保持完全一致。

### 检查 2：请求头里有没有 Authorization

在 Network 里点开一次 `/api/v1/claims/prepare` 请求：

- Headers → Request Headers：
  - 应该能看到类似：`Authorization: Bearer eyJhbGciOi...`

如果还是没有：

- 去 `authFetch.ts` 看，它是不是用 token 拼了这个 header；
- 没有的话，加上：

  ```ts
  const token = localStorage.getItem("<你的 jwt key>");
  if (token) {
    headers["Authorization"] = `Bearer ${token}`;
  }
  ```

### 检查 3：后端日志

当你再点一次「验证」：

- 不应该再看到 `UNAUTHORIZED`；
- 如果变成别的错误（例如 404 CLAIM_NOT_FOUND），那就说明**鉴权已经通过**，我们在处理后面的业务逻辑了。

---

## 不要在前端用 apiKey

后端提示 `allowedMethods: ["jwt","apiKey"]`，看起来好像可以“直接用 apiKey”，但注意：

- `apiKey` 是给**后端脚本 / 管理工具**用的，不适合塞进浏览器前端；
- 一旦写进前端代码，就等于把你的管理员钥匙公开给所有人。

所以前端这条路，**老老实实用 JWT + 钱包登录**是对的，你现在的改动方向完全没问题，只是少了这一步“在赔付管理页也走一次登录”。

---

你现在这一步其实很关键：  
前面 404 已经解决了，这个 401 过掉之后，赔付管理这条链路就真的连上后端了，后面再慢慢打磨 UI 和字段就行。
