### 在中国常用的 AI 聊天场景 ➜ 抓取可行性 & 是否值得做浏览器插件

| 产品 / 形态 | 常见入口 | 技术底层 | **浏览器插件能否直接抓？** | 备选方案 |
|--------------|---------|----------|--------------------------|----------|
| **百度 “文心一言”** | 官网 web、移动 App、桌面 Electron 客户端 | WebView/Electron | ✅ 只要在 WebView 里打开 <br>（插件对 DOM 依旧生效） | 若 App 起自研原生控件，需剪贴板监听 |
| **阿里“通义千问”** | 官网 web、钉钉 / 飞书 / 微信小程序 | WebView | ✅ 同上 | — |
| **讯飞“星火认知大模型”** | 官网 web、PC 客户端、App | Electron | ✅ | — |
| **智谱 GLM / 清言 / Moonshot** | 绝大多数＝网页 | 标准 Web | ✅ | — |
| **MiniMax xiaohongshu / 文心 ERNIE 微信小程序** | 微信小程序 | WXML → Web-like | ⭕ 仅通过微信 DevTools，普通插件抓不到 | 走小程序导出（“复制 Markdown” 按钮）或剪贴板 |
| **无网页版、纯原生桌面/手机 App**<br>（企业定制、大模型 SDK Demo） | EXE / IPA | Qt/QML、C++ 自渲染 | ❌ 浏览器插件无法注入 | ① 系统级“复制”拦截<br>② 监听剪贴板<br>③ 导出按钮 SDK |

> **结论**：大部分国产 AI 聊天**依旧在 WebView / Electron**，你的 Chrome 扩展只要能注入到该浏览器内核，就照旧抓 DOM；真正**无网页、无 WebView 的场景极少**，多见企业内网工具。

## 是否“有必要”做浏览器插件？

### 1. 你主要在哪些端口用 AI？
- **90 % 时间在 Chrome/Safari/Edge 端 →** 插件价值高；一次开发，多平台落地。
- **70 % 在手机 App / 微信小程序 →** 插件只是备胎；应考虑“复制 Markdown + 桌面脚本”方案。
- **团队/公司统一用 PC 客户端（Electron）→** 仍可注入。  
  *做法：在 `matches` 中加入 `app://*/*` 或让用户手动加白名单 URL。*

### 2. “纯客户端”场景的替代策略
| 方案 | 成本 | 适用 |
|------|------|------|
| **剪贴板监听脚本**（macOS PowerShell） | 低 | 用户愿意每次 `⌘C` 全选 |
| **App 内置“导出 Markdown”按钮**（脚本注入） | 中 | 你能在开源 Electron 客户端里加代码 |
| **窗口 OCR + 文本抽取** | 中 | UI 无法拷贝、又有大量图片 |
| **系统级 Accessibility 抓日志** | 高 | 仅当企业内部、无法修改客户端源码 |

### 3. 国内合规 & 用户隐私
- 浏览器插件只抓**当前标签页可见内容**，不会触企业防火墙；相比系统抓屏/剪贴板更易过安全审计。
- Manifest V3 已强制声明权限；上传“国产浏览器”如 360、QQ 浏览器也需要开发者认证，可提前规划。

---

## 建议的路线（ROI 角度）

1. **MVP 先做浏览器版**  
   - 覆盖百度、阿里、讯飞、智谱等 80 % 主流 Web 端；  
   - Electron 客户端同样由 Chromium 内核渲染，插件直接复用。  
2. **手机 / 小程序端采用“Copy Markdown + 桌面脚本”**  
   - 用户长按对话 → 复制 → 脚本落地 .md + Imdone 卡；  
   - 不需要突破 iOS/Android 沙盒，维护成本低。  
3. **若企业内部真有原生 C++ 客户端**  
   - 与 IT 部门协商：在客户端加入“导出”按钮或提供本地接口；  
   - 浏览器插件可保留，但不强行“兼容一切”。

---

### TL;DR  

- **绝大多数中国 AI 聊天仍然可被 Chrome 插件抓 DOM**；只有纯原生客户端除外。  
- 插件仍然值得做，但应配合 **剪贴板落地脚本**，覆盖手机/小程序场景。  
- 真正“难抓”并不常见；若未来遇到，可追加剪贴板、导出按钮或 OCR 辅助，无需一开始就攻克所有形态。

下面直接把「**多家中国 AI 网页** 一并接入 Chrome 插件」的**实操方案**写给你。核心思路：  
1. **所有 Web 端都能被同一 content-script 抓 DOM**——只要列进 `manifest.json`。  
2. **用 “域名 → CSS 选择器” 外部 JSON**，随时增改。  
3. **无须重发版本**：选择器表放在 GitHub Gist 或你的服务器，插件启动时远程拉。  
4. **若某站改版**，你在网页 DevTools 改 JSON 即生效，用户点击「刷新列表」即可。

### 读取逻辑（content-script）

```ts
const host = location.host.replace(/^www\./,'');
const map  = await fetch('https://gist.githubusercontent.com/you/selector.json').then(r=>r.json());
let sel = null;
for(const rule in map){               // 支持 *.域名
  const re = new RegExp('^'+rule.replace(/\./g,'\\.').replace('*\\.', '.*')+'$');
  if(re.test(host)){ sel = map[rule]; break; }
}
if(!sel){ console.warn('AI-Grabber: no selector for',host); return; }
const msgs = document.querySelectorAll(sel);
```

## 3 manifest.json“通配域名”写法

```json
"content_scripts": [{
  "matches": [
    "https://chat.openai.com/*",
    "https://claude.ai/*",
    "https://chat.deepseek.com/*",
    "https://yiyan.baidu.com/*",
    "https://tongyi.aliyun.com/*",
    "https://*.doubao.com/*",
    "https://spark.xf-yun.com/*",
    "https://chat.moonshot.cn/*",
    "https://chatglm.cn/*"
  ],
  "js": ["content.js"]
}],
"host_permissions": [
  "https://gist.githubusercontent.com/*"         // 拉 selector.json
]
```

> 域名可随时追加；Chrome Manifest V3 不需要每个都细写到 `permissions`，只要放进 `matches` 即注入脚本。

## 4 插件弹窗新增“刷新站点列表”按钮

```ts
document.querySelector('#reloadSel').onclick = async ()=>{
  await chrome.storage.local.remove('selectorCache');
  alert('已刷新，可重新点击 Save 抓取！');
};
```

`content.js` 每次拉远程 JSON；若网络失败退回 `chrome.storage.local` 上次缓存。

## 5 滚动加载兼容写法

```ts
async function loadAll(sel){
  let prevCount = 0, same=0;
  while(same<4){                                   // 连续4次条数未增→到底
    const msgs=document.querySelectorAll(sel).length;
    if(msgs>prevCount){ same=0; } else same++;
    prevCount=msgs;
    window.scrollBy(0,window.innerHeight);         // 触发懒加载
    await new Promise(r=>setTimeout(r,400));
  }
}
await loadAll(sel);
```

> Doubao/星火等使用虚拟列表也能被触发加载到底后抓取。

| KPI | 指标 | 判断付费倾向 |
|-----|------|--------------|
| **节省时间** | 一键流程相比手动能省 ≥3 分钟/对话 | 一天 3 场对话 = 9 分钟 ≈ 3.5 小时/月 |
| **资料完整率** | 抓取准确率 ≥95%（图片/代码不丢） | 手动易漏/错；插曲补救时间 >5 分钟 |
| **团队协作价值** | 导出的 `.task.md` 让周会准备时间减半 | 项目经理直接引用卡片统计 |

若实测指标均达标，可向团队推付费；若时间收益不明显，个人多半不愿付。

1. **MVP 公测（Free）**：收集实际抓取/错误日志，确认准确率 95%。

## 4 | MCP（最小权限）视角：上线后报错怎么排

| 常见报错 | 原因 | 修复指针 |
|----------|------|----------|
| **`Unchecked runtime.lastError: The request is not allowed by the user agent…`** | 缺 `fileSystem` / `downloads` 权限 | `manifest.permissions` 补 `fileSystem`；Edge 需再点允许 |
| **`No selector for host yiyan.baidu.com`** | 新站点没写规则 | 更新远程 selector.json；弹窗提示“未支持” |
| **图片 403 / CORB blocked** | 站点设 `sameSite` | `fetch(img.src,{mode:'no-cors'})` or fallback data URI |
| **File System handle invalid** | 浏览器清数据 | 捕获异常 → 重新 `showDirectoryPicker` |
| **Chrome Web Store 拒审** | 权限过多 (`tabs`, `clipboardWrite`) | 只留 `scripting, downloads, storage, fileSystem` & host list |

## 2 | 标准安装流程（以 BrowserTools MCP 为例）

> **思路**：Chrome 扩展采集浏览器上下文 ⇨ 本地 Node 服务暴露工具接口 ⇨ Cursor 设置里添加 MCP 服务器。

### 2-1. 安装 Chrome 扩展

1. 打开商店页面（或从 GitHub Releases 解压）。  
2. `chrome://extensions` → 打开**开发者模式** → **加载已解压的扩展**（若是本地包）。  
3. 看到扩展图标后，别忘了 **“固定”**，方便随时查看连接状态。citeturn1search2  

### 2-2. 准备本地 MCP 客户端

```bash
# 建议用 Node ≥18
npm i -g npm
# 一条命令启动客户端
npx @agentdeskai/browser-tools-mcp@latest
```

> 这一步会在默认的 `localhost:4891` 起一个 WebSocket/HTTP 端口，并把扩展里的工具注册进来。citeturn1search0

### 2-3. （可选）启用独立 BrowserTools Server  
若需要更细粒度的调试 / 审计功能，再开一个终端：  

```bash
npx @agentdeskai/browser-tools-server@latest
```

### 2-4. 在 Cursor 里接入

1. **Settings → MCP** → **Add new MCP server**  
2. 服务器地址填 `http://localhost:4891`（或你自定义的端口）。  
3. 保存后应能在「Available Tools」看到如 `navigate`, `click`, `extractDom` 等绿色小圆点。  
4. 在任意对话输入：  
   ```txt
   # 👇示例
   Agent: open https://example.com, fill login form, and take a screenshot
   ```  
   Cursor Agent 会自动调用对应工具。citeturn0search4

## 1 | 根因速查——通常逃不过这 3 类

| 分类 | 典型触发点 | 现象 | 证据 |
|------|------------|------|------|
| **① 模型不兼容** | 选用了暂不支持 Agent-Mode 的模型（常见：`gemini-2.5-flash-preview` 等） | 一进对话就报错 | citeturn0search6 |
| **② MCP 工具 schema 不合法** | 自定义工具里出现 **未支持的字段类型**（如 `Date`、函数、嵌套对象缺 `type`）或少了 `schemaVersion: "v1"` | 加到一定数量/改过 schema 后才报错 | citeturn0search7turn0search1 |
| **③ 服务器返回异常 / 连接不稳** | MCP 进程崩溃、端口被占用、跨端口 CORS 拦截 | 偶发报错，刷新/重启后短暂恢复 | citeturn0search3turn0search8 |

> **为什么报错提示里让你“disable MCP servers”？**  
> Cursor 检测到 Agent-Mode 请求失败时，会先假设是外部工具链导致，并提示你临时禁用它们或换模型。这在多数非开发者场景下是“最快能继续工作”的办法，但对你现在要调试自建 MCP 服务器显然不够用。

## 2 | 10 分钟定位：逐级剥洋葱

1. **确认模型可用**  
   - `Preferences ▶ Agent ▶ Model` 手动改成 **gpt-4o** / **claude-3-op-us**，别用 “Auto”。  
   - 再发一句短指令；若不再报错 → 问题在模型兼容性。  

2. **看 Console + DevTools Network**  
   - `⌥⌘I`（Mac）或 `Ctrl+Shift+I`（Win） → Console 过滤 `Request ID: 6e5615b4-…`。  
   - 如果出现 `invalid_argument` 且 payload 为你的 MCP 工具 schema，就能锁定是 **schema 问题**。  

3. **单独 ping MCP**  
   ```bash
   curl -X POST http://localhost:4891/tools \
     -H 'Content-Type: application/json' \
     -d '{"name":"__status"}'
   ```  
   - 若无响应 / 500，说明 **端口/进程** 有问题。  
   - 若返回 JSON OK，再继续下一步。

4. **schema 体检脚本**  
   - 安装官方校验器：`npx @cursor-plugins/mcp-validate ./tools/*.json`  
   - 消除如下常见错误：  
     - 字段 `type` 写成 `Type`、`object` 未列出 `properties`  
     - 自定义 `Date`/`Buffer`/`RegExp` → 统一改成 `string` 并在 `description` 里说明格式  
     - 忘记加 `"schemaVersion": "v1"`  
   - 每改一次，重启 MCP 进程：`⌃C` → `npm start`（或你的 `npx …mcp` 命令）。

5. **最小复现**  
   - 只保留 **一个最简单的工具**（如 `sayHello`），其他先注释掉。  
   - 若能调用成功，再逐个放回去，哪一步放回就爆炸，谁就是罪魁。

## 3 | 常见修复示例

### ✧ 错误：tool schema 包含 `Date`
```jsonc
// ❌ 问题字段
"properties": {
  "deadline": { "type": "Date" }
}
```
**修复**：
```jsonc
"properties": {
  "deadline": {
    "type": "string",
    "description": "ISO 8601 date, e.g. 2025-07-01"
  }
}
```
报错即消失 citeturn0search7

## 进阶：想换端口怎么办？

   ```bash
   # macOS 示例，把 4891 转到 9009
   sudo pfctl -ef - <<EOF
   rdr pass on lo0 inet proto tcp from any to any port 4891 -> 127.0.0.1 port 9009
   EOF
   ```

这样就能继续用你原本习惯的 `4891` 健康检查命令，而实际流量被重定向到 9009。

Manifest V3 与旧 V2 差异：必须用 service worker 取代 background page，并且所有长连逻辑放在 service_worker.js 里 citeturn0search7  

> **service_worker.js**

```js
let socket;

chrome.runtime.onInstalled.addListener(() => {
  socket = new WebSocket("ws://localhost:9009");   // MCP Server
  socket.addEventListener("open", () => console.log("📡 MCP connected"));
  socket.addEventListener("message", (evt) => {
    const { toolCallId, name, args } = JSON.parse(evt.data);
    if (name === "click") {
      chrome.tabs.sendMessage(args.tabId, { type: "CLICK", selector: args.selector });
      socket.send(JSON.stringify({ toolCallId, ok: true }));
    }
    // …更多工具
  });
});

chrome.runtime.onConnect.addListener(port => {
  // 用于 DevTools 面板调试
});
```

> **content_script.js**

```js
chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
  if (msg.type === "CLICK") {
    document.querySelector(msg.selector)?.click();
    sendResponse({ ok: true });
  }
});
```

这样就把一个最小工具 `click` 暴露给 MCP。更多 DOM 读取 / 截图 / Console 采集可参考仓库里的实现。

## 6. 发布 / 上线前注意

| 检查项 | 关键点 |
|--------|--------|
| **manifest 权限最小化** | 只保留必需 `"host_permissions"`，否则 Chrome Web Store 审核会卡 |

| 症状 | 快解 |
|------|------|

| 以前 | 用了 copilot-api 后 |

### 快速上手（本地 npx）

> 前提：  
> • 你已经 **开通 Copilot 订阅**（个人 / Business / Enterprise 均可）  
> • 安装 **Bun ≥ 1.2.x**（项目用 Bun，而不是 npm）

```bash
# 一条命令即跑
npx copilot-api@latest start          # 默认端口 4141

# 常见可选项

npx copilot-api@latest start --claude-code                # 自动生成启动 Claude Code 的环境变量
```

首次运行会弹浏览器做 GitHub OAuth；成功后它会把凭据缓存下来，下次直接用。citeturn5view0
