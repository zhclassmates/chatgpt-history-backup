```bash
# 设置你的备份硬盘路径（请根据你硬盘名称修改）

echo "✅ 所有核心数据已备份到 $BACKUP_DISK/mac_backup/"
```

- 备份了你桌面、文档、浏览器数据、SSH、VSCode插件配置等

### ✅ 第一步：确定是否插入成功

请按照以下步骤操作：

1. 插上硬盘
2. 打开 **“访达 Finder”**
3. 在顶部菜单点击：**访达 > 设置 > 边栏**
4. 确保 “外部磁盘” 是 ✅ 勾选的
5. 然后切换到 **“通用”** 标签页，也勾选“外部磁盘”

这样你才能在“访达左侧栏”和“桌面”看到磁盘。

---

### ✅ 第二步：打开“磁盘工具 Disk Utility”检查状态

#### 操作步骤：

1. 点击 Launchpad（或 Spotlight 搜索）→ 打开“磁盘工具”
2. 点击左上角“显示所有设备”
3. 在左侧栏你应该能看到你的硬盘（即使没挂载）

查看这几点：

| 状态 | 解释 | 应对方法 |
|------|------|----------|
| 显示为“灰色”，名字在但不能打开 | 没有挂载 | 点顶部【挂载】按钮试试 |
| 没有分区，只显示磁盘编号 | 未格式化 | 需要重新格式化为 APFS |
| 出现错误标志 | 文件系统损坏 | 可尝试“急救”或重新格式化 |
| 能看到卷，但容量为 0 或不可读 | 磁盘损坏或加密异常 | 尝试“磁盘急救”，失败就重新格式化 |

---

### ✅ 第三步：是否你用了 APFS 加密？

如果你格式化时选择了 **“APFS（加密）”**，你每次插入时需要输入密码，否则无法挂载。

#### 解决办法：

1. 在“磁盘工具”里右键点击你的硬盘卷
2. 点击“挂载” → 输入你当时设置的密码

若你**忘记密码**，这个卷无法访问，只能格式化重新用。

---

### ✅ 第四步：终端命令检查硬盘状态（高级）

你可以打开“终端”，输入以下命令看看磁盘是否存在：

```bash
diskutil list
```

你会看到类似如下结果：

```
/dev/disk2 (external, physical):
   #: TYPE              NAME          SIZE       IDENTIFIER
   0: GUID_partition_scheme            *500.1 GB  disk2
   1: APFS Container Scheme -          500.1 GB   disk2s2
     APFS Volume       MyBackup        250.0 GB   disk3s1
```

如果 `diskutil list` 能看到你硬盘，但 Finder 没显示，那说明只是**未挂载或权限问题**。

---

## 🛠️ 如果你确定磁盘是空的，可以格式化一遍：

### 步骤（会清空硬盘）：

1. 打开“磁盘工具”
2. 左侧选中硬盘最上层（不是子卷）
3. 点击【抹掉】
4. 设置：
   - 名称：`MyBackup`
   - 格式：`APFS`（不要选加密）
   - 方案：`GUID 分区图`

5. 点击“抹掉”，等几秒钟即可完成

完成后你的磁盘会在访达中自动出现，路径为：

```
/Volumes/MyBackup
```

## 2 | 两种部署模式

| 模式 | 用户体验 | 计算/存储 | 隐私合规 | 成本结构 | 典型技术栈 |
|------|----------|-----------|-----------|-----------|------------|

## 3 | 关键流程（两模式共通）

1. **数据采集**  
   - 用户上传 30 秒–2 分钟干净语音（或你提供公开角色数据集）。

4. **推理接口**  
   - 文本转语音(TTS)+Voice Conversion 双路：既可直接克隆朗读，也可把已有音频转成目标音色。

> **记忆占用**  
> - 16 GB 可以跑 batch_size = 4 的 so-vits-svc（fp32）。  
> - 若启用 `cache_all_data`，预处理数据 < 3 GB 时仍能一次性装下。

---

#### ⏱️ 为什么比 Windows/NVIDIA 慢？

- Apple MPS 后端目前 **不支持 FP16/混合精度**；同样 step 会比 CUDA 大约慢 2–3×。  
- so-vits-svc 的 **检索索引 (faiss)** 仍只能在 CPU 跑，提高了 inference 延迟。

---

#### 🔧 加速小技巧

1. **把步数压到 8 k – 12 k**  
   多数中文/英文说话声 10 min 数据在 8 k step 就能过关。  
   《Few tips to train your vocal model》作者也推荐 9–11 kciteturn4search4  
2. **裁成 < 10 s 语音段**  
   步长＝`总切片数 ÷ batch_size`，切得短可显著减少每 epoch 时长。  
3. **开启 `cache_all_data`**（内存够时）  
   同样数据量 M4 会少一次 I/O，能提速 15 %–20 %。  
4. **转投 GPT-SoVITS**  
   1 分钟数据 + few-shot 微调，质量直逼传统 10 k step，且官方脚本已标注 “Apple silicon 测试通过”citeturn8view0。

### 1. `prep.sh` —— 语料预处理

```bash
#!/usr/bin/env bash
set -e
FILE=$1          # raw 音/视频
NAME=${2:-my_voice}

# 依赖：brew install ffmpeg && pip install pydub ffmpeg-python webrtcvad
python <<'PY'
import sys, os, ffmpeg, webrtcvad, soundfile as sf, numpy as np
from pydub import AudioSegment
file, name = sys.argv[1], sys.argv[2]
os.makedirs(f"dataset/{name}", exist_ok=True)

# A 提取 16 kHz mono WAV
ffmpeg.input(file).output("tmp.wav", ac=1, ar=16000).overwrite_output().run(quiet=True)

# B VAD 切片
audio, sr = sf.read("tmp.wav")
pcm = (audio * 32768).astype(np.int16).tobytes()
vad, frame = webrtcvad.Vad(3), 480  # 30 ms
chunks, started = [], None
for i in range(0, len(pcm), frame*2):
    if i+frame*2 > len(pcm): break
    voiced = vad.is_speech(pcm[i:i+frame*2], 16000)
    if voiced and started is None: started = i
    if not voiced and started is not None:
        chunks.append((started,i))
        started = None
if started: chunks.append((started,len(pcm)))

# C 保存片段
for idx,(s,e) in enumerate(chunks):
    if (e-s)/2 < sr*1: continue   # <1 s 丢弃
    clip = audio[int(s/2):int(e/2)]
    sf.write(f"dataset/{name}/{idx:05}.wav", clip, sr)
os.remove("tmp.wav")
PY
chmod +x prep.sh
```

### 2. `train_fewshot.sh` —— GPT-SoVITS 微调

```bash
#!/usr/bin/env bash
set -e
NAME=${1:-my_voice}
# 依赖：pip install gpt-sovits  (官方 repo)
python gpt_sovits/train.py \
       --data_dir dataset/$NAME \
       --exp_name $NAME \
       --device mps \
       --gpt_epochs 40 \
       --sovits_epochs 30
chmod +x train_fewshot.sh
```

## 1 | **FunClip 对片段时长的要求**

**问题**：FunClip 在处理对话时，对每个片段的时长会有要求，通常是 **超过一定时长的有效语音段**，例如 **超过 1 秒** 才会被识别和处理，过短的音频片段（比如几毫秒的静音或填充音）会被丢弃。

### 解决方案：
1. **过滤短片段**  
   你可以在 **语音预处理** 时，先过滤掉过短的片段，保留 **1 秒以上的有效片段**，这样 FunClip 才能正常处理。

   使用 `pydub` 或 `librosa` 来裁剪短片段，可以写一个简单的脚本：

   ```python
   from pydub import AudioSegment

   def remove_short_clips(input_dir, min_duration=1000):
       """
       过滤掉小于 min_duration（毫秒）的音频片段
       """
       for file_name in os.listdir(input_dir):
           if file_name.endswith(".wav"):
               audio = AudioSegment.from_wav(os.path.join(input_dir, file_name))
               if len(audio) >= min_duration:
                   audio.export(os.path.join(input_dir, file_name), format="wav")

   # 调用方法
   remove_short_clips("dataset/spk0")
   ```

### **2. 加载和使用 Hubert 模型**

```python
from transformers import HubertForCTC, Wav2Vec2Processor
import torch
import librosa

# 加载Hubert模型和处理器
model_name = "facebook/hubert-base-ls960"  # 选择基础模型或较大模型

with torch.no_grad():

predicted_ids = torch.argmax(logits, dim=-1)
```

### 1. **浏览器的扩展程序和设置**
如果你在 Chrome 中安装了 **Cursor 编辑器**的扩展，或者与其相关的任何插件，可以按照以下步骤清除：

#### 删除扩展和插件：
1. 打开 **Chrome 浏览器**。
2. 在地址栏输入 `chrome://extensions/`，进入扩展程序页面。
3. 找到与 **Cursor** 相关的扩展，点击 **删除** 按钮。

### 2. **Chrome 用户数据中的 Cursor 相关痕迹**
Chrome 会在用户数据目录中保存大量浏览记录、插件数据、缓存等信息。如果有与 **Cursor 编辑器** 相关的文件，它们通常会保存在用户数据目录。

#### 清除 **User Data** 中的 **Cursor** 路径：
```bash
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/Extensions/com.cursor.*
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/Local\ Storage/*
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/Cookies
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/History
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/IndexedDB/*
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/Top\ Sites
```

这会删除 Chrome 用户数据文件夹中关于 **Cursor 编辑器** 或其他任何扩展和缓存的数据。

### 3. **清理 Chrome 配置文件中的 Cursor 跟踪数据**
一些 Chrome 的设置文件可能会保存与 **Cursor 编辑器** 相关的配置，如配置、书签、历史记录等。删除以下文件可以清除这些跟踪信息。

#### 删除配置文件：
```bash
rm -rf ~/Library/Application\ Support/Google/Chrome/Preferences
rm -rf ~/Library/Application\ Support/Google/Chrome/Bookmarked\ Pages
```

### 4. **清理浏览历史和缓存**
清除与 **Cursor** 相关的历史记录和缓存，避免浏览器存储网站信息。

#### 删除 Chrome 浏览历史：
```bash
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/History
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/History Provider
```

#### 删除缓存文件：
```bash
rm -rf ~/Library/Application\ Support/Google/Chrome/User\ Data/Default/Cache/*
```

### 5. **使用 Chrome 清除浏览数据功能**
你也可以通过 **Chrome 设置** 中提供的 **清除浏览数据** 功能清理痕迹：
1. 打开 **Chrome 浏览器**。
2. 点击右上角的三个竖点（更多菜单）。
3. 选择 **设置** → **隐私与安全** → **清除浏览数据**。
4. 在弹出框中，选择 **时间范围：全部时间**，然后勾选：
   - 浏览历史记录
   - 缓存的图片和文件
   - Cookies 及其他站点数据
   - 扩展程序数据（如果需要）
