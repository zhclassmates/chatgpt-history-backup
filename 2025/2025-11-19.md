### 1. 先确认它是谁（用 DevTools）

你截图里右上角已经开了「选择元素」工具：

3. 用鼠标指到黑框上，点一下。


或者某个 `Drawer` / `PreviewPanel` 之类的组件根节点。


黑框立刻消失，就说明你找对元素了。

---

根据你在 Elements 里看到的 class / 组件名，到项目代码里搜：

- 如果是简单 `<div>`，就直接删掉这一块 JSX；


或者干脆：


这不是神秘黑洞，就是一个铺满右侧的 `<div>` 或组件。用 DevTools 点一下 → 找到 DOM → 要么 `display: none`，要么在 React 代码里把对应的那一块删掉/关掉，就干净了。

## 0/ 核心思路：只上链「哈希 + 时间 + 谁签」

别想复杂了，V0 做这几件事就够：

- 证据本体（JSON、一堆文件）放 **本地 / 数据库 / S3 / IPFS**
- 链上只存一条记录：
  - `claimId`：你自己定义的理赔/订单 ID（做成 `bytes32`）
  - `bundleHash`：整包证据的哈希（Merkle root 或直接 keccak(JSON)）
  - `timestamp`：上链时间
  - `submitter`：哪个钱包提交的（你的「验证者钱包」）

这样你就有一句话可讲：**“任何人可以拿到这份 JSON，自行哈一遍，对比链上哈希，一致就证明没作假。”**

---

## 1/ 超简智能合约（证据登记本）

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title EvidenceRegistry - 极简证据上链登记本
/// @notice 只存哈希，不存隐私数据
contract EvidenceRegistry {
    struct Evidence {
        bytes32 bundleHash;   // 证据包哈希 (Merkle root / keccak(json))
        uint64  timestamp;    // 上链时间
        address submitter;    // 提交人（你的验证者钱包）
    }

    // 你指定一个“验证者地址”，只有这个地址能提交
    address public attestor;

    // key = claimId（例如 claim 内部 UUID / keccak(orderRef + "-v1")）
    mapping(bytes32 => Evidence) public evidences;

    event EvidenceSubmitted(
        bytes32 indexed claimId,
        bytes32 indexed bundleHash,
        address indexed submitter,
        uint64  timestamp
    );

    constructor(address _attestor) {
        require(_attestor != address(0), "attestor required");
        attestor = _attestor;
    }

    /// @notice 为某个 claim 写入一条证据，只能写一次，不能覆盖
    function submitEvidence(bytes32 claimId, bytes32 bundleHash) external {
        require(msg.sender == attestor, "not attestor");
        require(claimId != bytes32(0), "empty claimId");
        require(bundleHash != bytes32(0), "empty hash");
        require(evidences[claimId].timestamp == 0, "already exists");

        evidences[claimId] = Evidence({
            bundleHash: bundleHash,
            timestamp: uint64(block.timestamp),
            submitter: msg.sender
        });

        emit EvidenceSubmitted(
            claimId,
            bundleHash,
            msg.sender,
            uint64(block.timestamp)
        );
    }
}
```

特点：

- 没有继承 OpenZeppelin，**尽量少依赖**，方便你 Remix 直接部署。
- 逻辑极简：
  - 只允许 `attestor` 写入；
  - 同一个 `claimId` **只能写一次**（防止事后改证据）。
- 查询：
  - `evidences(claimId)` 是 `public mapping`，区块浏览器会自动生成 getter，直接查。

### 步骤 2：算一个 `bundleHash`

随便用 Node / Python，都行。例如 Node：


- 在 Remix / 浏览器里调用 `evidences(claimId)`
  - 可以看到 `(bundleHash, timestamp, submitter)`
- 任意人拿到你这份 JSON：
  - 本地跑一遍 keccak
  - 对比链上的 `bundleHash`
  - 若一致 = 你没动过数据；不一致 = 有人改了

---

## 3/ 后面你项目怎么接这个合约

现在你只需要记住几件事：

1. **claims 表**里增加两个字段：
   - `onchainClaimId`（bytes32，字符串存成 hex）
   - `onchainEvidenceHash`（bytes32）
2. 你现在的 `POST /admin/evidence/onchain` V0 版本可以只做一件事：
   - 从 DB 里拿到 claim 的 `claimId` & `bundleHash`
   - 后端用 `ISSUER_PRIVATE_KEY` 调合约 `submitEvidence`
   - 把 `txHash` 写回 `claims` 表（你之前说要“查看链上交易”那个按钮就能用了）
3. 理赔详情页里只展示：

   - 链上哈希：`bundleHash`
   - 链上交易：`txHash`（点一下跳到 BaseScan）
   - 提交时间：区块时间（或者 DB 中保存的）
