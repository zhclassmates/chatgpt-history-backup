## 概览

要在 Chrome 扩展中集成《周易》卦象查询并利用大模型增强解释，可以采用全本地化、开源、免费的方案：在用户设备上部署小规模、高效的开源大模型（如 Llama 2、Mistral、Qwen 系列），结合量化与推理优化技术（如 llama.cpp、GPTQ），再搭配检索增强生成（RAG）架构，以 FAISS、Chroma 或 Milvus 等向量数据库提供高效上下文检索。整体流程无需依赖云 API，可保证数据隐私、零成本调用，且在普通 GPU 或 CPU 环境下具备良好性能。

## 一、开源大模型本地部署

### 1. Llama 2 系列  
- **模型来源**：Meta 发布 Llama 2 开源且免费供非商业用途下载，社区迭代活跃 citeturn0news13。  
- **推理框架**：  
  - **llama.cpp**：C/C++ 移植，支持 4 位量化，在 M1/M2 Mac、Linux、Windows 上本地运行，最低资源占用 citeturn0search0。  
  - **Hugging Face Transformers + 🤗Accelerate**：通过 Python 接口加载官方权重，适合有 Python 开发环境者 citeturn0search1。  
  - **vLLM**：Meta 推荐的高性能 Python-only 推理引擎，兼容 Llama 2，支持 OpenAI 接口 citeturn1search2turn1search3。  
  - **Ollama / LM Studio / Anakin AI**：零代码图形化工具，可在本地快速部署并调用 Llama 2 模型 citeturn0search4turn1search5。

### 2. Mistral 系列  
- **模型特性**：Mistral 7B、Mixtral 8×7B 等均已 Apache 2.0 开源，可自行下载部署 citeturn1search6。  
- **部署方案**：  
  - 利用 **vLLM** 或 **TensorRT-LLM/TGI** 做高效推理，官方文档提供完整自部署指南 citeturn1search2turn1search3。  
  - **Ollama** 框架支持一键安装 Mistral 模型，友好界面利于非专业用户 citeturn1search5。  

### 3. Qwen 系列  
- **开源声明**：阿里巴巴开放 Qwen-1.8B/7B/14B/72B 及 Chat 版本模型，并持续更新 citeturn2news12turn2search0。  
- **本地部署**：  
  - 官方 GitHub 提供 Int4/Int8 量化权重，可直接下载并结合 llama.cpp、vLLM 使用 citeturn2search1turn2search2。  
  - Qwen2.5-Omni 支持多模态，官方示例展示 Docker + vLLM 部署流程 citeturn2search3。

## 二、模型优化与量化

- **低精度量化**：采用 GPTQ、llama.cpp 内置量化工具，将模型从 FP16 / FP32 量化至 Int4 / Int8，显著降低显存占用且几乎无感官损失 citeturn0search0。  
- **裁剪与蒸馏**：可在开源社区寻找蒸馏版小模型（如 Llama 2-7B-Chat、Mistral Small、Qwen-7B-Chat），进一步提升推理速度 citeturn0search1。  
- **混合精度与流水线并行**：在支持的推理框架（vLLM、TensorRT-LLM）中开启混合精度，配合流水线并行，提升 GPU 利用率 citeturn1search3。

---

## 三、检索增强生成（RAG）方案

将卦辞、爻辞文本与书籍注释等资料构建知识库，结合向量检索与大模型生成，实现精准解释。

1. **嵌入生成**  
   使用 Sentence Transformers、OpenAI Embeddings 或 Hugging Face Embeddings，将全文转为向量 citeturn0search1turn3search3。  
2. **向量存储与检索**  
   - **FAISS**（Meta 提供，GPU/CPU 均支持，高性能相似性搜索） citeturn3search0。

## 概要

## 一、基础 GPT API 调用

### 1. ChatCompletion 生成解释  
- 调用 OpenAI 的 **ChatCompletion** 接口，传入用户的卦象编号与模板 Prompt，让 GPT 返回“GPT 增强解释” citeturn0search1。  
- 通过设置 `temperature`、`max_tokens` 等参数，可控制回答风格与长度。

### 2. Embeddings 接口实现语义匹配  
- 使用 **Embeddings API** 将卦辞、爻辞、EPUB 文本等转为向量，并存入向量数据库 citeturn0search1。  
- 用户查询时同样调用**Embeddings**，并与向量库做相似度搜索，为 GPT 提供上下文。

## 二、检索增强生成（RAG）

### 1. 语义检索与文件搜索  
- **Semantic Search for GPTs**：OpenAI 原生支持检索上传资料（如 FAQ、文档），通过语义搜索获取相关片段，无需自行搭建向量库 citeturn0search0。  
- **文件搜索（Responses API）**：利用 Responses API 的 File Search 功能，一次调用即可完成文档上传、检索和生成，显著简化架构 citeturn0search6。

### 2. 向量数据库方案  
- **Pinecone**：业界常用托管向量库，与 GPT-4 配合效果良好，示例展示了如何先检索再传入 GPT 生成答案 citeturn0search1。  
- **Elasticsearch**：用于检索的成熟方案，再结合 ChatCompletion 做 RAG citeturn0search3。  
- **DIY RAG 教程**：诸多教程（如 RAG 从零到一）可快速上手，帮助理解核心流程 citeturn0search5.

### 3. Prompt 拼接  
将检索到的 Top‑k 文本与用户输入拼入模版：  
```text
“卦象编号：{upper}/{lower}/{change}。相关卦辞：{retrieved_text}。请基于以上信息给出现代化解读。”
```  
然后交由 GPT 生成融合解释。

Google 浏览器（Chrome）占用内存多，主要有以下几个原因：

---

### 1. **多进程架构**
Chrome 使用所谓的“多进程架构”（每个标签页、插件、扩展甚至部分网站都单独运行在自己的进程中），这虽然提升了**稳定性**和**安全性**，但也导致内存占用上升。

- 一个页面崩溃不会导致整个浏览器崩溃。
- 每个进程都要分配一套内存资源（如运行环境、线程、堆栈等），造成冗余。

---

### 2. **预渲染与缓存**
Chrome 会为提升速度预加载你可能会点击的网页，比如你输入一个网址还没回车，它就开始预加载了。此外，它还会大量使用缓存（图片、脚本、页面内容）来提高打开速度，这些都会占用内存。

---

### 3. **扩展程序/插件消耗**
安装的扩展插件（如广告拦截器、密码管理器、主题等）每一个都是单独的后台脚本，也会持续占用内存，甚至有些插件存在内存泄漏的问题。

---

### 4. **现代网页越来越重**
如今的网站比过去复杂得多，有大量的 JavaScript、动态内容、图像、视频、动画等，Chrome 为了流畅地运行这些网页，会分配更多资源。

---

### 5. **垃圾回收机制不够激进**
Chrome 使用 JavaScript 引擎 V8，自带垃圾回收机制，但它不会频繁地清理内存，以避免频繁回收带来的性能下降。这种“温和”的策略可能导致内存长时间得不到释放。

---

### 如何缓解：
- 定期关闭不用的标签页。
- 删除或禁用不必要的扩展程序。
- 使用 Chrome 的任务管理器（`Shift+Esc`）查看哪些标签或扩展占用内存最多。
- 考虑使用“标签页休眠”插件或 Chrome 自带的内存节省功能（Memory Saver）。
- 重启浏览器释放长期积累的内存。

import json
import time

def json_to_netscape(json_file, netscape_file):
    with open(json_file, 'r') as f:
        cookies = json.load(f)
    
    with open(netscape_file, 'w') as f:
        # Writing the header
        f.write('# Netscape HTTP Cookie File\n')
        f.write('# This is a generated file!  Do not edit.\n\n')
        
        for cookie in cookies:
            # Checking if the cookie is for youtube.com
            if cookie.get('domain') and '.youtube.com' in cookie['domain']:
                domain = cookie['domain']
                path = cookie.get('path', '/')
                secure = 'TRUE' if cookie.get('secure') else 'FALSE'
                expiry = int(cookie.get('expirationDate', time.time()))
                name = cookie['name']
                value = cookie['value']
                # Writing in Netscape format
                f.write(f"{domain}\tTRUE\t{path}\t{secure}\t{expiry}\t{name}\t{value}\n")

# Example usage

netscape_file = 'cookies.txt'  # The output Netscape format file
