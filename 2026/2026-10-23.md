计算机科学中，**蒙特卡洛模拟（Monte Carlo Simulation）**属于一大类数学与计算方法：利用计算机进行模拟、搜索、优化、预测和决策。

如果你的目标是利用 AI 研究投资策略、理解复杂市场、提高决策质量，那么值得系统了解的不只是蒙特卡洛，还有下面这些方法。

## 一、计算机科学中值得掌握的 12 种方法

| 方法 | 核心思想 | 在金融和 AI 中的应用 |
|---|---|---|
| **1. 蒙特卡洛模拟** | 大量随机试验，估计结果分布 | 计算策略亏损概率、最大回撤 |
| **2. 贝叶斯推断** | 根据新证据不断更新判断 | 动态更新投资假设的可信度 |

| **5. 强化学习 RL** | 通过行动、奖励和反馈学习 | AI 自主探索交易策略 |
| **6. 遗传算法 GA** | 模拟进化、选择、变异 | 搜索策略参数和规则组合 |

## 二、蒙特卡洛模拟究竟在做什么？

假设你研究出一套 BTC 交易策略，想知道它未来可能产生什么结果。

你不能只问：

“这套策略未来一年能赚多少钱？”

更合理的问题是：

“在不同市场路径下，它可能赚多少、亏多少，以及出现严重亏损的概率是多少？”

蒙特卡洛的价值不是预测唯一结果，而是**揭示不同结果的概率与风险范围**。

## 四、最值得你优先学习的五种

结合你正在构建的 AI 自主研究与低频投资决策系统，我建议按以下顺序：

1. **贝叶斯推断**：解决“新信息出现后，我应该如何改变原来的判断”。
2. **因果推断**：解决“市场为什么上涨，什么是真正的驱动因素”。
3. **蒙特卡洛模拟**：解决“即使我的判断正确，仍然可能遭受多大损失”。
4. **贝叶斯优化**：解决“有限算力和研究预算应该优先测试什么”。
5. **鲁棒优化**：解决“什么策略在市场环境改变后仍有机会存活”。

强化学习和 MCTS 可以放在后面。它们适合序贯决策，但需要可靠的环境模型和奖励设计，否则容易学到模拟器中的虚假规律。

**更重要的认识是：计算机不只是用来存储信息、运行程序，还可以用来扩展人的推理能力。**

你可以把这些方法分成四个基本问题：

**如何认识世界（统计与推断）→ 如何解释世界（因果）→ 如何探索可能性（模拟与搜索）→ 如何选择行动（优化与决策）。**

这四个问题，正好可以作为你未来个人思考系统和 AI 研究系统的方法论基础。

你的意思可以归纳成一个原则：

**不要让软件规定自己的工作方式，而是让软件适应自己的思考方式、操作习惯和创造流程。**

在 AI 时代，软件不再只是一个需要学习如何使用的工具，也可以成为一个能够持续改造的工具。

这意味着，你对 MacDown、Markdown 编辑器、insidebar.ai 等工具的思路应该发生变化。

### 1. 从适应软件，转向改造软件

例如 Markdown 编辑器：

- **快捷键**：高频操作按照自己的肌肉记忆重新设置。
- **内部链接**：输入 `[[概念名称]]`，直接跳转到另一篇文档。
- **页面关系**：不仅能跳转，还能查看哪些文档引用了当前文档。
- **AI 辅助**：选中文字，就能让 AI 帮助质疑、寻找反证、补充资料、整理思路。
- **思考记录**：每次修改都保留时间、原始观点和改变原因。
- **自动归档**：AI 对话中产生的重要结论，可以直接写入 Markdown 文件。

不必要求某一个软件原生支持所有功能。可以通过插件、脚本、开源代码修改或多个工具组合实现。

### 2. 真正需要设计的不是编辑器，而是创造流程

### 3. 但改造也需要遵守一个原则

**不是所有能改造的东西都值得改造。**

改造本身也消耗时间。应该优先改造那些高频、重复、容易出错、妨碍思考连续性的操作。

可以用一个简单的判断：

\[
改造价值=\frac{长期节省的时间+新增能力的价值}{开发成本+维护成本}
\]

这不是精确的经济模型，而是帮助你判断改造优先级的原则。

### 4. 我认为最重要的转变

以前是：

**学习软件 → 适应软件 → 使用软件完成任务。**

现在可以变成：

**明确自己的目标 → 设计自己的流程 → 选择或改造软件 → 实际使用 → 根据反馈继续改造。**

对于你正在构建的长期思考系统，建议先确定一套稳定的 Markdown 文档格式和链接规则，再围绕它改造编辑器与 AI 对话入口。

这样即使以后换掉 MacDown、VMark 或 insidebar.ai，你积累的知识、思考记录和工作流程也不会跟着消失。

**最终目标不是拥有一套功能最多的软件，而是建立一套能够随着你的认知和需求不断进化的个人创造系统。**

# insidebar-ai 源码逆向分析与改造审查

**审查对象：** <Link url="https://github.com/xiaolai/insidebar-ai" title="xiaolai/insidebar-ai"/>  
**源码版本：** v1.7.2，基于 GitHub commit `f1373d66`  
**审查方式：** 直接读取 GitHub 仓库源码，对照附件中的既有分析。  
**执行边界：** 只分析，不修改仓库。

## 一、核心结论

**insidebar-ai 适合作为个人 AI 对话采集入口，但目前不适合直接充当可靠的长期知识存储系统。**

源码已经具备三个重要能力：

1. 从 ChatGPT 等 AI 网页 DOM 提取对话，并转换成 Markdown。
2. 通过浏览器扩展的 Service Worker 将对话保存到 IndexedDB。
3. 使用原始会话 ID 识别已有对话，在内容变化时更新本地记录。

但也确认了三个问题：

| 问题 | 源码验证 | 对个人文档系统的影响 |
|---|---|---|
| 长对话截断 | 内容上限为 100,000 个字符，超出直接截断 | 保存后可能缺失内容 |
| 消息结构丢失 | 提取时有 `messages[]`，持久化时未保存 | 不利于逐轮分析、链接和自动整理 |
| 缺少可靠的外部同步机制 | 当前保存路径只有本地数据库写入 | 无法保证 Markdown 文档与对话持续一致 |

这三项问题分别可以在 [history-manager.js](https://github.com/xiaolai/insidebar-ai/blob/f1373d66a2e589db0c1d381fd6fe792751ba5052/modules/history-manager.js#L9-L14)、[chatgpt-history-extractor.js](https://github.com/xiaolai/insidebar-ai/blob/f1373d66a2e589db0c1d381fd6fe792751ba5052/content-scripts/chatgpt-history-extractor.js#L319-L338) 和 [service-worker.js](https://github.com/xiaolai/insidebar-ai/blob/f1373d66a2e589db0c1d381fd6fe792751ba5052/background/service-worker.js#L395-L447) 中核查。

从你的最终目标来看，改造的重点不应仅是增加一个“同步 Markdown”按钮，而是建立：

**AI 对话 → 可靠采集 → 原始记录 → 文档同步 → 人工思考整理 → 修改历史 → 持续迭代。**

其中，“保存原始记录”和“形成经过思考的知识文档”应当是两个不同的过程。

## 二、对原分析报告的关键纠正

这次复核发现了比原报告更重要的源码问题。

| 优先级 | 发现 | 结论 |
|---|---|---|
| P0 | 侧边栏手动保存、编辑直接调用 `history-manager.js` | 只在 Service Worker 添加同步钩子会漏数据 |
| P0 | `querySelectorAll(A) \|\| querySelectorAll(B)` | 备用选择器实际上不会执行 |
| P1 | Service Worker 与 Side Panel 都处理 `checkDuplicateConversation` | 存在响应竞争与查重误判风险 |
| P1 | `conversationId` 索引不是唯一索引 | 并发保存可能产生重复记录 |
| P1 | 保存完成响应未等待 IndexedDB 整个事务提交 | 不适合作为可靠同步确认机制 |
| P1 | `timestamp` 来自 `Date.now()` | 表示抓取时间，不代表对话真正发生时间 |

其中，消息响应竞争还得到 Chrome 官方消息机制的支持：当多个监听器回复同一消息时，只有最先的回复生效。<Cite ref="turn133925search0"/>

## 四、改造顺序与验收

| 阶段 | 核心工作 | 验收要求 |
