## 🔧 项目概述

## 🧩 系统组成

### 1. 直播间端（采样 + 控制）

- **电机系统**：使用皮带结构控制滑台，X/Y/Z 三轴分别用于：
  - 前进/后退（X）
  - 左右移动（Y）
  - Z轴升降+取样（电磁或伺服+机械爪）
- **取样模块**：
  - 摄像头实时识别瓜子，记录形状（可选择轮廓提取）
  - 或使用简单轮廓扫描+照片合成处理
- **通信模块**：
  - ESP32 连接 WiFi，和微信小程序后台 API 通信
- **小程序控制接口**：
  - 用户点击按钮 → 电机执行取样 → 拍摄照片 → 转换为 STl/矢量轮廓数据

---

### 2. 用户端（3D 打印机）

- **硬件结构**：由废旧光驱改装
  - 常见方案：两个或三个光驱作为 X/Y/Z 轴滑台，精度够做小模型
  - 控制主板：Arduino Nano + A4988 驱动 + GRBL 固件
- **软件端**：
  - 使用微信小程序接收服务器 STL 数据
  - 调用串口（通过本地小程序+转发服务或 USB Host）上传 G-code
- **打印材质**：
  - 热熔胶、低温塑料、固化墨水（可用简化方案，非标准PLA）

## 1. 设备直接接入云端（ESP32/ESP8266 Wi‑Fi 直连）

### 🧩 架构
```
[小程序]
    ↓ HTTPS/WebSocket
[云服务器]
    ↓ MQTT / WebSocket
[ESP32 打印机模块]
    ↓ UART
[Arduino + 光驱机构]
```

- **原理**：把打印机端的 Arduino 换成或外挂一个 ESP32/ESP8266，直接连入 Wi‑Fi，订阅云端下发的打印任务（STL/G‑code）。
- **流程**：
  1. 小程序调用云函数 `triggerPrint(taskId)`（HTTPS 或 WebSocket）。
  2. 云端通过 MQTT Broker（或 WebSocket）推送任务到指定设备 ID 的 ESP。
  3. ESP32 拿到任务后，通过串口（UART）下发 G‑code 给 Arduino，执行打印。
- **优点**：
  - 真正做到“手机 → 云 → 设备”，无需用户在本地安装任何桌面程序。
  - 部署灵活，只需给每台设备刷入固件并配置 Wi‑Fi/设备 ID。
- **缺点**：
  - 需要在设备端维护一个 MQTT/WebSocket 客户端。
  - 对网络依赖强，必须保证打印机安装环境有可靠 Wi‑Fi。

## 2. 微信小程序蓝牙直连（局域网／近场）

### 🧩 架构
```
[小程序 BLE API]
    ↔ BLE
[ESP32（或 NRF52）蓝牙模块]
    ↓ UART
[Arduino + 光驱机构]
```

- **原理**：利用微信小程序提供的 BLE API，直接把手机与打印机（外挂蓝牙模块）配对，手机下发 G‑code 给打印机端的蓝牙模块。
- **流程**：
  1. 小程序页面调用 `wx.openBluetoothAdapter` → 扫描/连接打印机BLE设备。
  2. 建立 BLE 连接后，用 `wx.writeBLECharacteristicValue` 发送 G‑code 命令。
  3. 蓝牙模块转发到 Arduino 执行打印。
- **优点**：
  - 无需云服务器，全程局域网/近场直连，实时性好。
  - 适合同一屋檐下的用户，调试简单。
- **缺点**：
  - 只能在手机与打印机物理距离＜10 m 范围内使用，不支持远程打印。
  - 小程序 BLE 接口相对复杂，需要处理配对、特征值、MTU 分包等。

### 🧩 架构
```
[小程序]
    ↓ 调用微信 IoT Cloud API
[微信 IoT Cloud]
    ↓ 下发消息
[ESP32 + 微信 IoT SDK]
    ↓ UART
[Arduino + 光驱机构]
```

- **原理**：利用微信官方的 IoT 云（https://iot.weixin.qq.com），小程序直接调用腾讯云的物联网平台接口，设备端接入微信 IoT SDK，实现消息下发与状态上报。

  1. 小程序通过云函数或客户端 SDK 调用微信 IoT Cloud “下发消息”。
  2. 设备端（ESP32 刷入微信 IoT 固件）自动收到消息回调。
  3. ESP32 转发给 Arduino 执行打印。

  - 官方解决方案，安全可靠，支持鉴权、双向通信。

## 4. 本地局域网 HTTP Server（无需额外 App，但需在本地网络）

### 🧩 架构
```
[小程序]
    ↓ wx.request（局域网 IP ）
[打印机本地 HTTP 服务]
    ↓ UART
[Arduino + 光驱机构]
```

- **原理**：在本地网络中，给打印机连接的树莓派或电脑上跑一个轻量 HTTP Server（例如 Flask、Express），小程序直接请求局域网地址触发打印。
- **流程**：
  1. 小程序调用 `wx.request({ url: "http://192.168.1.123:5000/print", data: { task } })`。
  2. 本地 Server 接收并下发命令给 Arduino。
- **优点**：
  - 简单直接，几乎零云端成本。
  - 同样适合同一局域网环境下的远程打印（手机连同一 Wi‑Fi）。
- **缺点**：
  - 依赖用户必须将手机和打印机部署在同一个局域网。
  - 无法跨网段/跨互联网使用。

## 二、关键优化点

| 环节           | 优化思路                                   | 预估延时     |
|--------------|------------------------------------------|------------|
| 1. 小程序 → WS | **持久化连接**<br>消息体极简（只发任务ID） | ~10–50 ms  |
| 2. WS → MQTT | WS 服务进程内直调 MQTT 客户端（同机房）      | ~5–20 ms   |
| 3. Broker → 设备 | **QoS=0** 无重发、单包下发<br>持久化 TCP   | ~10–100 ms |

1. **选对机房／可用区**

3. **MQTT Broker**  
   统一在 `user/{uid}/control/motor` 订阅所有电机指令。

## 4️⃣ 设备端：ESP32 + Arduino 固件

ESP32 负责接收 MQTT 消息并转发给 Arduino，Arduino 驱动 A4988/DRV8825 步进电机。

### ESP32 伪码
```cpp
void onMqttMessage(const String &topic, const String &payload) {
  ControlMsg msg = parseJson(payload);
  // 直接通过 Serial1/UART1 转给 Arduino
  Serial1.write(encodeForArduino(msg));
}
```

### Arduino 伪码
```cpp
void loop() {
  if (Serial1.available()) {
    MotorCmd cmd = readCmdFromSerial();
    switch (cmd.axis) {
      case 'X': stepperX.move(cmd.direction, cmd.speed, cmd.steps); break;
      case 'Y': stepperY.move(...); break;
      case 'Z': stepperZ.move(...); break;
      case 'R': stepperR.move(...); break;
    }
  }
}
```

- **stepper.move(dir, speed, steps)**：  
  - 如果 `steps==0`，启动一个持续移动；  
  - 如果 `steps>0`，移动到指定步数后自动停止。  
- **stop** 动作可由步进库内部检测停止信号或接收专门的 stop 命令。

## 5️⃣ 安全与限位

- **限位开关**  
  - 在每个轴的行程终点接限位开关，防止过冲。  
- **速度/行程上限**  
  - 小程序端对 `speed` 和 `steps` 做白名单校验；  
  - 设备端再次校验，超出值直接丢弃或限制到安全范围。  
- **疲劳保护**  
  - 连续操作超过 N 秒后强制停止，提示用户“请稍作休息再操作”。

---

## 6️⃣ 用户体验优化

- **即时响应**：电机动作一开始就回传“ACK”给小程序，界面立刻显示“正在移动”，无感知延迟。  
- **实时状态**：设备端定时（如 50 ms 一次）上报当前轴位置/速度给小程序，用于滑块 + 位置指示。  
- **UI 滑块**：在按钮旁边加可拖动的滑块，用户可通过滑块设置 `speed` 或 `steps`，更灵活。

- **ESP32**：持久订阅 `user/{uid}/control/motor`，`user/{uid}/control/sequence` Topics，收到 JSON 立刻通过串口转给 Arduino。

## 一、流程回顾

1. **小程序建立长连接**

## 🧠 控制代码（Arduino Nano）V1.0

我们采用 **软件串口 + 步进电机控制 + 限位归零 + 指令触发** 框架：

```cpp
#include <SoftwareSerial.h>

#define STEP_PIN 2
#define DIR_PIN 3
#define LIMIT_SWITCH_PIN 4
#define BUZZER_PIN 5

SoftwareSerial espSerial(8, 9); // RX, TX

void setup() {
  pinMode(STEP_PIN, OUTPUT);
  pinMode(DIR_PIN, OUTPUT);
  pinMode(LIMIT_SWITCH_PIN, INPUT_PULLUP);
  pinMode(BUZZER_PIN, OUTPUT);

  digitalWrite(DIR_PIN, LOW); // 默认方向
  espSerial.begin(9600);
  Serial.begin(9600);
  delay(1000);
  
  Serial.println("初始化中，开始归位...");
  goHome(); // 初始化归位
}

void loop() {
  if (espSerial.available()) {
    String command = espSerial.readStringUntil('\n');
    command.trim();
    if (command == "poke") {
      Serial.println("收到指令：poke");
      doPoke();
    }
  }
}

// 拨动动作
void doPoke() {
  digitalWrite(DIR_PIN, HIGH);
  for (int i = 0; i < 800; i++) { // 播动800步，可调
    digitalWrite(STEP_PIN, HIGH);
    delayMicroseconds(800);
    digitalWrite(STEP_PIN, LOW);
    delayMicroseconds(800);
  }
  delay(300);
  goHome();
  beep();
}

// 回原点
void goHome() {
  digitalWrite(DIR_PIN, LOW);
  while (digitalRead(LIMIT_SWITCH_PIN) == HIGH) {
    digitalWrite(STEP_PIN, HIGH);
    delayMicroseconds(800);
    digitalWrite(STEP_PIN, LOW);
    delayMicroseconds(800);
  }
  Serial.println("已归位");
}

// 响一声提示
void beep() {
  digitalWrite(BUZZER_PIN, HIGH);
  delay(100);
  digitalWrite(BUZZER_PIN, LOW);
}
```

## 🧠 “双向通信”的意思是：

除了小程序向硬件发送指令，**硬件也可以把信息反馈回来给小程序**，比如：

| 场景                            | 回传内容示例                    |

| 电机当前速度                     | `currentSpeed: 15`              |
| 当前执行状态（运行/完成）       | `status: done`                  |
| 电机当前位置（角度或圈数）       | `angle: 180°` 或 `step: 1024`   |
| 故障信息（电机卡死等）           | `error: motor blocked`          |

---

## 🔧 如何实现双向通信？

### 方法一：小程序定时向 ESP8266 请求状态
小程序轮询 ESP8266 提供的 `/status` 接口。

```js
setInterval(() => {
  wx.request({
    url: 'http://192.168.4.1/status',
    success(res) {
      console.log("设备状态：", res.data);
    }
  })
}, 2000);
```

ESP8266 返回一个 JSON：

```json
{
  "speed": 15,
  "status": "running",
  "angle": 90
}
```

### 方法二：WebSocket（实时推送）
> 小程序建立 WebSocket 连接，ESP8266 实时推送状态（更复杂，但实时性强）

    motorStatus: {
      speed: 0,
      direction: '未知',
      position: 0,
      limitSwitch: false
    }
  },

  onLoad() {

  },

  connectWebSocket() {
    wx.connectSocket({
      url: 'ws://192.168.4.1:81', // 你ESP8266的IP地址
      success: () => {
        this.setData({ isConnected: true })
      }
    })

    wx.onSocketMessage((res) => {
      const status = JSON.parse(res.data)
      this.setData({ motorStatus: status })
    })
  },

  sendCommand(cmd, value = null) {
    const msg = JSON.stringify({ cmd, value })
    wx.sendSocketMessage({ data: msg })
  },

  startMotor() { this.sendCommand('start') },
  stopMotor() { this.sendCommand('stop') },
  speedUp() { this.sendCommand('speedUp') },
  speedDown() { this.sendCommand('speedDown') },
  reverseMotor() { this.sendCommand('reverse') },
})

| 格式 | 参数错误 | ESP 解析失败 | ✅ 用 JSON 或标准 key=value 方式传参 |
| 编码 | 中文乱码 | ESP 不支持中文 | ✅ 小程序转码后再发送（或用拼音/英文） |

void handleControl() {

void loop() {
  if (Serial.available()) {
    String cmd = Serial.readStringUntil('\n');
    int commaIndex = cmd.indexOf(',');
    String dir = cmd.substring(0, commaIndex);
    int spd = cmd.substring(commaIndex + 1).toInt();

    myStepper.setSpeed(spd);

    if (dir == "CW") {
      myStepper.step(stepsPerRevolution); // 顺时针一圈
    } else if (dir == "CCW") {
      myStepper.step(-stepsPerRevolution); // 逆时针
    }
  }
}

const deviceIP = 'http://192.168.4.1';

function sendCommand(dir, speed) {

  });
}
