## 第二步：每一句拆成词块

> Ich = 我，heiße = 叫，Nico = Nico

本地不行，核心原因不是 HTML 错，而是 **iPhone 打开本地 HTML 时，经常不是“真正网页环境”**。

主要有 4 个坑：

## 1. iPhone 文件 App 打开 HTML，多数是“预览”，不是网页

你点 `.html` 文件时，iPhone 可能用 **文件预览 / Quick Look** 打开。

它能显示文字，但：

```text
JavaScript 可能不执行
按钮可能没反应
speechSynthesis 朗读接口可能不能用
```

你的朗读功能靠的是浏览器里的：

```js
speechSynthesis
```

如果 JS 不跑，就没声音。

---

## 2. 微信 / Telegram / 邮件里打开，也可能是内置浏览器

这些 App 打开 HTML，经常是自己的 WebView。  
它们对本地文件、语音、自动播放限制很多。

结果就是：

```text
页面能看
按钮能点
但是不朗读
```

---

## 3. Safari 对 file:// 本地文件权限很保守

本地 HTML 的地址一般是：

```text
file://...
```

而不是：

```text
http://...
https://...
```

很多浏览器功能在 `file://` 下会被限制。  
语音朗读、声音播放、脚本权限，都会被系统安全机制夹住脖子。

---

## 4. 朗读需要“网页 + 用户点击 + 系统语音”

你的页面必须满足：

```text
真正 Safari 网页环境
用户点击触发
系统有德语语音
```

本地文件经常只满足第一个的一半。

```text
直接点本地文件打开，不稳定
```


## 为什么不优先 PWA

PWA 的好处是真的：

```text
加到主屏幕
像 App 一样打开
不用 App Store
不用苹果开发者账号
```

但你的关键功能是**录音**。网页录音要用浏览器麦克风接口，通常要求 HTTPS 或 localhost 这种安全环境；普通服务器 IP 的 HTTP 页面可能拿不到麦克风权限。MDN 对 `getUserMedia()` 也明确写了它只在安全上下文可用，并且需要用户授权。citeturn617968view0

另外，网页朗读可以用 Web Speech API。它确实分成文字转语音 `SpeechSynthesis` 和语音识别 `SpeechRecognition` 两块。citeturn547858view0 其中朗读比较稳，`SpeechSynthesis` 是广泛可用的功能。citeturn547858view2 但语音识别不是所有主流浏览器都稳定支持，MDN 标的是 Limited availability。citeturn547858view1

## 所以你该选哪个？

你现在已经有 Mac，目标是省时间学德语。

我建议：

```text
不要做 PWA
继续做 iOS 自用 App
```

原因：

```text
1. 不用服务器
2. 不用 HTTPS
3. 不用备案
4. 不用 GitHub
5. 录音和回放更稳
6. 所有录音留在手机本地
```

PWA 看起来轻，但会把你拖进：

```text
托管
HTTPS
iPhone Safari 权限
缓存
离线
麦克风兼容
```

这些都是“学习时间黑洞”。
