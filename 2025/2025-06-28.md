下面给你一套**可落地的信息分层方案**，专门解决：

1. **Markdown 写就的源码仓库巨大**——各种 `.js / .py / .sql / .md / 图片` 混在一起。

3. **需要多种视图**：时间轴、进度列、立项/完结归档……随时一键切换。

## ① 目录分层：把“任务”与“代码/文档”物理隔离

```
my-project/
├─ src/              # 纯代码
├─ docs/             # 长文档 / 设计 / 规范
├─ assets/           # 图片、图纸、原型
├─ .imdone/          # ↙︎ 只放任务卡 (markdown)
│   ├─ backlog/
│   ├─ doing/
│   ├─ review/
│   ├─ done/
│   └─ archive/2024/
└─ README.md
```

- **优点**：  
  - 看板只扫描 `.imdone/`，源码文件不会变卡片。  
  - Git diff 一眼分清“业务代码改了”还是“任务状态改了”。  
- **设置**：Imdone → *Board Settings* → **“Board root = .imdone”**。

## ② 一张任务卡 = 一个 `.md` 文件（或 TODO 注释）

```markdown
# ♻️ 重构登录模块
status: doing
priority: 2
due: 2025-07-15
tags: [backend, refactor]

<!-- 任何需求、验收标准，都写在正文 -->
- [x] 支持 OAuth2
- [ ] 单测覆盖率 ≥ 90%
```

- **元数据**（status, priority, due）可写在 YAML front-matter 或 `key: value`。  
- **正文**可引用源码： `src/auth/login.js:45`；Imdone 在 VS Code 有“跳行”插件。

## ③ 多个“过滤视图” = 多种看板

| 想看的角度 | 搜索 / 过滤语法 | 保存为 Filtered List 后效果 |
|-----------|----------------|---------------------------|
| **进度列**（默认） | status 列分 backlog/doing/review/done | 拖拽即改 `status:` |
| **时间轴** | `due<=2025-07-31` 排序：due asc | 形成甘特条 | 
| **立项池** | `status:proposal` | 专门评审新需求 |
| **完结归档** | `status:done AND closed>2024-12-31` | 只看今年完成物 |

操作：搜索框输入 → 右侧 💾 **Save as “Timeline / Proposal / 年度归档”** → 侧栏随点随切。

## ④ 自动“把 TODO 变卡片”——保持代码与看板同步

```js
// src/auth/login.js
// TODO(#backend #p1 due:2025-07-10): 把登录逻辑迁移到 hooks
```

1. Imdone 扫描整个仓库时会把 `TODO:` 注释自动生成卡片，放在 **backlog**。  
2. 卡片字段来源：行内标签 `#backend`、`due:2025-07-10`。  
3. 在看板拖到 **doing** 时，Imdone 反向写回文件头，保持单一事实源。

## 3  Imdone 配置：只扫你想让它扫的东西

`.imdone/config.yml`（每个项目一份）

```yaml
# 只让 Imdone 把 .imdone/ 下的 md 视为任务，
# 也可以放宽到 TODO 注释（例子给出二选一）
include:
  - ".imdone/**/*.md"           # A. 纯任务文件
  # - "src/**/*.{js,py}"        # B. 代码 TODO；需要就取消注释
extensions:
  - md                          # 视为 Markdown 渲染
fields:                         # 常用元数据字段
  - status
  - priority
  - due
  - project
ignore:                         # 无需扫描的目录/文件
  - "node_modules/**"
  - "assets/**"
  - "**/*.png"
```

> 默认 *Imdone* 只解析文本后缀（md/js/py…）；你把图片目录排进 `ignore`，它根本不会尝试读 PNG/JPG，因此看板保持纯净citeturn8search4。

## 2  文件命名 & 后缀：三条可选规则

| 方案 | 文件长什么样 | 配置写法 | 适用场景 |

- **代码、图片、说明书** 永远不会变成卡，保持目录干净；

| 痛点 | 方案如何解决 |
|------|-------------|
| **文件成千上万，看板会不会被淹没？** | `include` 只扫任务后缀/目录；其他后缀全部 `ignore`。 |

### “一块看板里到底放多少卡才合适？”——**极简 Kanban 指南**

> 结论先说：**活跃卡 ≤ 25 张**，**每列 ≤ 7 张**；超出的就隐藏、折叠、归档或放进子清单。  
> 再少就失去看板价值，再多就看不见重点——这是一线团队（硬件、软件、内容创作都一样）最常见、最顺手的阈值。

| 规则 | 为什么 | 具体做法（只用看板自带功能，不接 CI、不写脚本） |
|------|--------|---------------------------------------------|
| **1. 活跃卡 ≤ 25 张** | 25 张≈一屏能扫完；再多大脑开始“选择性失明” | - 设 *自动归档*：Done ➜ 24 h 后移出<br>- 非本周事项放 **Backlog/Next** 视图，默认隐藏 |
| **2. 每列上限 5–7** | 列≥8 张时眼睛无法快速定位下一个动作 | 看板设置 **WIP Limit**：Doing=5、Review=3<br>超过后列头/背景变红，提醒先清库存 |
| **3. 一卡一主题** | 凝练到一句话才能拖动决策 | 标题 30 字内：`🅱 固件 OTA Bug`<br>子任务写在卡内 `- [ ]` checklist，不再拆新卡 |
| **4. 临时想法另设“收纳池”** | 碎念不占主线焦点 | 右侧放 **💡Inbox** 列；周五清零<br>留下的再拖进 Backlog |

## 1 | 让卡片“跳”到项目文件／文件夹

|-----------------|------------|

import sys, os, datetime, openai, textwrap

resp = openai.ChatCompletion.create(
  model="gpt-4o-mini",

### 2-A Imdone-watch.sh（Mac/Linux 一行脚本）

```bash
#!/usr/bin/env bash
watchfolder="$HOME/Shortcuts/Projects"
inotifywait -m -e create "$watchfolder" --format '%w%f' |
while read file; do
  [[ $file == *.md ]] || continue
  # 取项目名、文件名
  proj=$(echo "$file" | awk -F'/' '{for(i=1;i<=NF;i++) if($i=="Projects"){print $(i+1);exit}}')
  title=$(basename "$file" .md | cut -d_ -f2-)
  # 生成任务卡
  carddir="$watchfolder/../$proj/.imdone/backlog"
  mkdir -p "$carddir"
  cat > "$carddir/📝_${title}.task.md" <<EOF
# 📝 ${title//_/ }
link: ../ideas/$(basename "$file")
status: backlog
type: idea
EOF
done
```

* 依赖 `inotify-tools`（Linux）或 `fswatch`（macOS Homebrew）。  
* 将 `watchfolder` 替换成你的云盘根目录。

## 2 | 示例脚本：save-idea.sh

```bash
#!/usr/bin/env bash
# 用法：save-idea.sh <ProjectName> "<Idea Title>"

proj="$1"
title="$2"
slug="${title// /_}"
date=$(date +%F)
base="$HOME/Projects/$proj"

idea_dir="$base/ideas"
card_dir="$base/.imdone/backlog"

mkdir -p "$idea_dir" "$card_dir"

idea_path="$idea_dir/${date}_${slug}.md"
card_path="$card_dir/📝_${slug}.task.md"

# 写剪贴板 → Markdown 文件
pbpaste > "$idea_path"                 # macOS；Linux 用 xclip -o > …

# 若已装 imdone CLI，可直接调用；否则用 echo 生成 .task.md
if command -v imdone &>/dev/null; then
  imdone add \
    --title "📝 ${title}" \
    --field link="../ideas/$(basename "$idea_path")" \
    --field type=idea \
    --project-root "$base"
else
  cat > "$card_path" <<EOF
# 📝 ${title}
link: ../ideas/$(basename "$idea_path")
type: idea
status: backlog
EOF
fi

echo "Saved: $idea_path"
```

     m.dataset.idx = i;                    // 确保懒加载后 idx 不变

## 那么 **`chat.md` 能不能“什么都装进去”？**

> **可以把绝大部分内容写进同一个 Markdown 文件**——文字、代码、LaTeX、超链接都没有问题。  
> **唯一需要“分文件”的通常只有二进制资源**（图片、附件）。下面是三种常见做法：

| 做法 | 体验 | 体积 | 适用场景 |
|------|------|------|----------|
| **① 分离式（推荐）**<br>Markdown 引用相对路径图片 `![p1](img/p1.png)` | - MD 文件清爽<br>- 图片原尺寸保留<br>- 一解压就能看 | `chat.md` 几十 KB + `img/` | 自己看 / 团队共享；可以随时重新压缩 |
| **② Base64 内嵌**<br>在 MD 中直接写 `![p1](data:image/png;base64,...)` | 单一文件，发一份就够 | 文件会暴涨（大图 ×1.3 倍） | 只想留一份“打印式”存档，不怕体积 |
| **③ HTML 单页**<br>导出成 .html（图片脚本都 inline） | 浏览器打开即还原 ChatGPT 样式 | 中等 | 需保留原色彩、数学公式渲染时最方便 |

**为什么方案①最常用？**  
- 图片依旧是 .png/.jpg → 以后想放 PPT 或做模型训练很方便  
- Markdown 渲染器（VS Code、Typora、Obsidian、GitHub）都能自动加载 `img/` 相对资源  
- 目录 + zip 的形式与常见的 “论文附录” / “Jupyter Notebook + figures” 习惯一致

## 2 │ 文件夹名 & Markdown 文件名 —— 默认 + 手动可改

| 字段 | 默认值（建议逻辑） | 用户可改示例 |
|------|------------------|--------------|
| **Folder** | `YYYY-MM-DD_HHMM_<用户首句截断>`<br>• 日期取**第一条消息**的 time<br>• “首句”截中文/英文前 8-10 个可显示字符 | `2025-07-10_LiDAR_Fusion`<br>`0710_无人机相机选型` |
| **Markdown 文件** | `00_概览.md` （确保同文件夹中不会重名） | `LiDAR_设计笔记.md` |

> **为什么** `00_概览.md`？——把 “00” 放最前，文件列表自然把概览顶到最上方；后续若拆分子条目可用 `01_…/02_…`。

## 3 │ Imdone 卡片设计

### 3-A. 建议字段模板

```markdown
# 📝 LiDAR Fusion
link: ../2025-07-10_LiDAR_Fusion/00_概览.md
status: backlog
type: idea
created: 2025-07-10T09:29
source: chat.openai.com
```

| 字段 | 用途 |
|------|------|
| `status` | 拖动列改变（backlog→doing→done） |
| `type`   | 固定写 `idea`；在过滤器里 `type:idea` 就能只看灵感 |
| `created` | **时间戳**，看板可按此排序 |
| `source`  | 双击可跳回原网页（可选） |

### 3-B. 按时间排序 / 分类

1. **列排序**  
   - Imdone → 列菜单 `Sort by ➜ created (ascending)`  
   - 最新 idea 永远在列底/顶（一屏内保持 <25 张）
2. **过滤视图**  
   - 「本周新想法」：`created>=2025-07-08 AND type:idea` → 保存为 *Week Ideas*  
   - 「今年全部」：`created>=2025-01-01`  
3. **时间泳道 / 分组** *(Imdone 2.5+ 支持)*  
   - 视图设置 ➜ *Group by* `created:month` → 看板横向出现 `2025-07`, `2025-08` 行
