在 Hostinger 购买的域名绑定到 AWS 免费云服务器（EC2 实例）时，核心就在于 **DNS 设置**。你有两种常用方案：

1. **直接在 Hostinger DNS 区添加 A/CNAME 记录**，将域名指向你的 EC2 弹性公网 IP。  
2. **使用 AWS Route 53 托管域名**，然后在 Hostinger 将域名的 Nameservers 改为 Route 53 提供的服务器。

下面将分别介绍这两种方法的详细步骤。

---

## 一、前置准备

- **获取 Elastic IP**  
  为避免 EC2 重启导致公网 IP 变化，建议在 AWS 控制台为实例分配一个 **弹性公网 IP（Elastic IP）**，并将其关联到你的实例上。  
- **安全组开放端口**  
  确保安全组入站规则允许 HTTP（80）和 HTTPS（443）端口访问；否则即便 DNS 配置正确，浏览器也无法访问你的网站。

---

## 二、方法一：在 Hostinger DNS 区直接添加记录

### 1. 进入 Hostinger DNS 区编辑器  
登陆到 hPanel → Domains → 你的域名 → **DNS / Nameservers → DNS Records**【citeturn0search4】

### 2. 添加 A 记录指向 Elastic IP  
- **Type**：A record  
- **Host**：`@`  
- **Points to**：你的 Elastic IP（如 `18.218.196.23`）  
- **TTL**：默认（3600 秒）  
> 这样根域名（example.com）就会指向到你的 EC2 实例citeturn0search1

### 3. 添加 CNAME 记录支持 `www`  
- **Type**：CNAME record  
- **Host**：`www`  
- **Points to**：`@` （或直接填你的主域名 `example.com`）  
- **TTL**：默认  
> 这样访问 `www.example.com` 时会重定向到根域名的 A 记录citeturn0search21

### 4. 等待 DNS 生效  
DNS 记录更新后，通常在 **几分钟到 24 小时** 内全球生效。完成后，在浏览器输入 `http://example.com` 即可访问。

---

## 三、方法二：通过 AWS Route 53 托管域名

> 如果你希望 AWS 完全接管 DNS，或后续需要用到更多 AWS DNS 功能（如流量分配、健康检查等），推荐使用此方案。

### 1. 在 Route 53 创建 Hosted Zone  
- 登录 AWS 控制台 → Route 53 → Hosted zones → **Create hosted zone**  
- **Domain name** 填写你的域名（`example.com`）  
- 点击 **Create**，此时会生成一组 AWS Nameservers（4 个）citeturn0search16

### 2. 在 Hosted Zone 中添加记录  
- **A record**  
  - **Record name**：留空（表示根域）  
  - **Value**：你的 Elastic IP  
- （可选）**CNAME record**  
  - **Record name**：`www`  
  - **Value**：根域（`example.com`）  
> 这一步与方法一中在 Hostinger 添加记录类似，只是操作界面在 AWSciteturn0search22

### 3. 在 Hostinger 修改 Nameservers  
登陆 hPanel → Domains → 你的域名 → **DNS / Nameservers → Nameservers**，选择 **Custom nameservers** 并填写 Route 53 提供的 4 个 NS 地址，比如：  
```
ns-123.awsdns-45.org  
ns-678.awsdns-90.co.uk  
ns-234.awsdns-56.com  
ns-567.awsdns-89.net  
```  
保存后 Hostinger 会把域名的权威 DNS 转给 AWS Route 53 来管理citeturn0search8

### 4. 等待 Nameservers 生效  
同样需要 **几分钟到数小时** 的全球 DNS 传播时间。传播完成后，Route 53 中的记录就生效了，访问 `example.com` 即可访问你的博客。

---

## 四、常见故障排查

1. **DNS 记录不生效**  
   - 使用 `dig example.com` 或者 `nslookup example.com` 检查是否已解析到你的 Elastic IP。  
2. **安全组/防火墙问题**  
   - 确认 EC2 的安全组和服务器上的 UFW/iptables 均已允许 80/443 端口访问。  
3. **Web 服务未启动**  
   - SSH 登录实例，执行 `sudo systemctl status nginx` 或 `apache2`，确保服务运行并监听 80 端口。  
4. **域名缓存**  
   - 本地 DNS 缓存可能延迟生效，使用 `sudo killall -HUP mDNSResponder`（macOS）或换用公共 DNS（8.8.8.8）重试。

- **正确的可用性测试方法**应该是通过 HTTP 请求：  
  ```bash
  curl -I http://3.132.144.172
  ```  
