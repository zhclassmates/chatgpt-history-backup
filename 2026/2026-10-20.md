# 币安新币做空研究系统：方案评估

**结论：这个方向值得单独研究，而且可以复用现有的量价研究方法。但必须把“币安上市”和“能够做空”分开。**

你的核心思路是：

1. 收集所有进入币安生态的新币，不再扫描整个加密市场。
2. 研究它们上市后不同阶段的价格、成交量变化。
3. 找出上涨结束、持续下跌或阶段性崩盘前的共同特征。
4. 通过历史回测寻找最有效的做空时机。
5. 只有存在真实可交易的合约、足够流动性和合理交易成本，才允许进入策略候选池。

你提出的“80% 的币最终下跌”可以作为**待验证假设**，不能直接当作统计事实。

尤其需要区分：

- 从历史最高点下跌 80%。
- 上市 30 天后价格下跌。
- 上市 90 天后价格下跌。
- 在某个可识别信号出现后，做空能否获得正收益。

这四件事完全不同。即使绝大多数代币最终下跌，也不代表做空它们容易赚钱。

## 一、币安的三类上币，已经核实

币安官方确认存在 Alpha、Futures、Spot 三种主要上市路径，而且**不要求每个代币严格按照 Alpha → 合约 → 现货的顺序上市**。<Cite ref="turn553969search8"/>

| 类型 | 含义 | 能否做空 | 研究价值 |
|---|---|---|---|
| Binance Alpha | 早期代币展示及交易入口 | 不能仅凭 Alpha 身份做空 | 高 |
| Binance Futures | 合约上市，包括永续合约 | 支持双向交易的合约可以做空 | 最高 |
| Binance Spot | 正式现货上市 | 普通现货不能直接做空；部分币可能支持杠杆借币 | 高 |

还有两点很重要：

- **Alpha 和 Futures 可以同时上市。** 例如 ZBT 于 2025 年 10 月 17 日先后开放 Alpha 和 USDT 永续合约交易，相差约 30 分钟。<Cite ref="turn553969search13"/>
- **合约上市不保证未来现货上市。** 币安官方对此有明确说明。<Cite ref="turn553969search13"/>

因此，数据库不能只存一个 `is_binance_listed` 字段，而应该分别保存三个市场的上市时间及状态。

第一阶段不要开发几十种技术指标，先保存可复算的原始数据。

  <divider color="subtle"/>

  <divider color="subtle"/>
  <text weight="medium">C. 合约历史表</text>

## 四、什么时候做空？应该研究哪些阶段？

我建议不要一开始就让 AI 寻找复杂指标，而是先研究三个时间起点。

| 起点 | 研究的问题 |
|---|---|
| Alpha 上市 | 早期热度消退后是否容易下跌？ |
| Futures 上市 | 合约开放后第几天开始出现可持续下跌？ |
| Spot 上市 | 正式现货上市是否成为阶段性顶部？ |

每个起点都观察上市后 1、3、7、14、30、60、90 天的表现。

再研究四种候选做空结构：

1. **上市冲高回落**：上市后快速上涨，随后跌破早期交易区间。
2. **缩量反弹失败**：已经下跌，反弹成交量不足，未能突破前高。
3. **放量破位**：价格跌破前期支撑，成交量显著增加。
4. **OI 与价格背离**：价格上涨、OI 增长，但随后上涨失败，研究是否存在拥挤仓位解除的机会。

这四种只是待检验假说，不是已经有效的信号。

特别注意：新币在下跌 70% 之前，可能先上涨 300%。如果没有明确的止损和仓位控制，最终看对方向也可能提前爆仓。

## 五、Alpha 阶段能否在其他交易所做空？

**可以，但必须逐币核实。**

一个代币进入 Binance Alpha 时，如果 Bybit、OKX、Bitget、Hyperliquid 等其他平台已经开放对应永续合约，就可能在那些平台做空。

但这与你提出的“只研究币安”存在范围冲突。

我的建议是：

**V1 只研究币安，优先研究 Binance Futures 上市后的做空机会。** Alpha 作为上市事件与历史数据来源，不急于接入其他交易所。

这样可以减少交易所间的数据口径差异、合约规则差异、流动性差异及维护成本。

建议按以下顺序推进：

- **幸存者偏差**：不能只抓今天还在交易的合约，否则会遗漏历史下架币。
- **未来信息泄漏**：不能用事后最高价定义当时的做空信号。
- **不可交易收益**：不能把没有合约、没有流动性或无法成交期间的下跌算成利润。

## 最终判断

我支持把这个方向建立为一个独立研究模块：

**Binance New Listing Short Research（币安新币做空研究）**

但不需要重新建设一套完整系统。可以复用现有研究框架的特征计算、规则搜索和回测逻辑，单独建立币安数据集。

目前已核实币安提供的市场分类和主要数据接口；**尚未实际拉取完整历史上市清单，也没有完成任何做空策略回测，因此还不能断言存在可盈利规律。**

最优先的工作不是开发交易机器人，而是先回答：

**币安过去两三年上市、且曾开放永续合约的代币，在上市后什么时间、什么量价结构下做空，扣除全部成本后的期望收益最高？**

这是整个项目最值得验证的核心问题。

# Binance API 完整数据能力调查

<text color="secondary" size="xs">调查范围：币安官方开发者文档 · 2026 年 10 月 20 日</text>

## 一、核心结论

币安 API 的数据能力远超过价格、成交量和 K 线。对你的**新币做空研究系统**，最有价值的是六类数据：

1. **上市生命周期**：Alpha、现货、永续合约、交割合约的市场状态与交易规则。
2. **价格与成交**：历史 K 线、逐笔成交、主动买卖成交量、交易笔数。
3. **合约仓位**：未平仓量 OI、OI 历史统计、大户多空持仓比例。
4. **合约定价**：资金费率、标记价格、指数价格、溢价指数。
5. **交易流动性**：盘口深度、买卖价差、实时订单簿变化。
6. **账户与执行**：杠杆、保证金、仓位、订单、成交、盈亏、风险状态。

但有一个重要限制：

**币安可以提供大量历史数据，却不保证所有指标都能回溯到代币上市第一天。**

尤其是 OI 统计、多空比例、盘口历史和某些 Alpha 数据，必须区分能回补的历史数据与需要自行持续采集的数据。

官方文档总入口：<Link url="https://developers.binance.com/en/docs/catalog" title="Binance Developer API Catalog"/>。官方将交易接口划分为现货、U 本位合约、币本位合约、期权、杠杆、钱包等模块。<Cite refs={["turn478169search0","turn478169search1"]}/>

### 3.2 一根 K 线究竟包含什么？

币安合约 K 线不只是常见的六个 OHLCV 字段，而是包含以下信息：

| 原始位置 | 字段 | 说明 |
|---|---|---|
| 0 | Open time | 开始时间 |
| 1 | Open | 开盘价 |
| 2 | High | 最高价 |
| 3 | Low | 最低价 |
| 4 | Close | 收盘价 |
| 5 | Volume | 基础资产成交量 |
| 6 | Close time | 结束时间 |
| 7 | Quote asset volume | 计价资产成交额 |
| 8 | Number of trades | 成交笔数 |
| 9 | Taker buy base volume | 主动买入基础资产数量 |
| 10 | Taker buy quote volume | 主动买入计价资产金额 |
| 11 | Ignore | 保留字段，不参与分析 |

例如在 `TOKENUSDT` 合约中：

- `Volume` 表示以 TOKEN 为单位的成交量。
- `Quote asset volume` 表示以 USDT 计价的成交额。
- `Taker buy quote volume` 可以用来计算主动买入成交额占比。
- 主动卖出成交额可以近似通过总成交额减去主动买入成交额计算。

这些信息能够直接用于研究**价格上涨但主动买盘减弱、放量滞涨、下跌放量、反弹成交不足**等结构。

我认为不是缺少 Harness²，也不是缺少更强大的回测框架。

**1. 自主发现研究本身的问题**

例如，AI 应该在开始研究前主动发现：

“历史市值字段缺失，无法可靠判断代币首次达到 100 万美元市值的时间，因此当前实验设计不成立。”

而不是等你发现后再调整。

**2. 自主决定下一轮应该研究什么**

假设第一轮发现成交量放大 3 倍的规则表现不错。

AI 不应该马上宣布找到规律，而应该主动检查：是不是牛市行情造成的？是不是只有少数大涨币贡献结果？换一个时间段是否还成立？交易成本是否吃掉收益？

然后自主决定下一轮实验。

**3. 自主判断什么时候停止**

如果一条规则经过样本外验证没有增量，就应该自动淘汰。

如果数据不足，就应该停止研究并提出补数任务，而不是继续搜索更多参数。

Harness² 有两层改进机制：

- 任务内部：提出不同执行方案，试运行并比较效果。
- 跨任务：保留有证据支持的改进，应用到未来任务。

官方报告在部分专业任务基准上获得明显提升，最高包括 WorkBuddy-Bench 的 11.5 分增益及 LAB 部分通过率的 11.8 个百分点增益。<Cite ref="turn541531search0"/>

但它的实验重点是 Agent 工作表现，而不是金融预测能力。

因此，我更倾向把它作为未来的自我优化模块，而不是第一阶段的研究引擎。

### 5. AlphaEvolve：证明自动算法发现可以有实际价值

Google DeepMind 的 <Entity category="software" value="AlphaEvolve" disambig="Google DeepMind evolutionary algorithm discovery agent"/> 采用：

**生成算法 → 自动评估 → 选择更优算法 → 继续演化。**

它在数学算法、数据中心调度和计算基础设施优化方面报告了实际成果，包括矩阵乘法算法的改进。<Cite ref="turn541531academia7"/>

其真正值得借鉴的不是某一个模型，而是它把“评价器”放在了系统中心。

AI 可以自由提出方案，但是否有效，由独立、可重复的程序来判断。

这与你的量化研究高度相关：AI 负责探索，确定性程序负责计算，封闭样本负责最终验证。

## 五、行业现在究竟成熟到什么程度？

根据 2026 年 8 月发布的 Agentic Quantitative Trading 综述，当前系统的研究仍主要集中在信号发现，完整连接组合构建、交易执行与风险控制的系统相对少见。预测能力强，也不一定转化为真实市场的交易收益。<Cite ref="turn914754academia6"/>

我将成熟度划分如下。这里是根据公开证据作出的工程判断，不是行业官方评级。

| 能力 | 当前成熟度 | 依据 |
|---|---|---|
| AI 自动生成研究假设 | 较成熟 | 多个项目已经实现 |
| 自动编写和运行实验 | 较成熟 | RD-Agent、AI Scientist |
| 自动选择下一轮实验 | 已有可用实现 | 反馈调度、树搜索 |
| 自动识别数据缺陷 | 部分实现 | 仍需专门验证器 |
| 长期研究记忆 | 发展中 | Harness² 等提供机制 |
| 跨市场稳定发现 Alpha | 未证实成熟 | 缺少充分的独立实盘证据 |
| 长期无人值守盈利 | 未证实成熟 | 研究结果不能替代实盘验证 |

因此，**自主研究的基础技术已经足够让你开始建设，但自主赚钱还远没有被证明。**

### 第一阶段：用现有数据做一次真正的自主研究实验

建议先用你已经开展的代币量价研究作为测试任务，不要立即扩展到多个市场。

研究目标固定为：

> 在真实可观察的代币历史数据中，自动发现能够提前识别后续显著上涨的量价规律，并检验其在未参与研究的数据中是否依然有效。

实验设计：

| 项目 | 约束 |
|---|---|
| 数据 | 先审计已有历史数据，不合格则停止 |
| 自主研究 | 最多 10 轮，无需人工逐轮指导 |
| 假设 | AI 自主生成，不预设必须使用哪些指标 |
| 验证 | 时间顺序切分，防止未来信息泄漏 |
| 对照 | 简单量价规则、随机或无信号基准 |
| 成本 | 设置固定 API 和计算预算 |
| 结果 | 保存所有实验，包括失败结果 |
| 交易 | 只研究和模拟，不允许实盘下单 |

这里必须注意：如果现有历史市值缺失，系统就不能假装能够研究“首次达到某个市值”的时机。应该先修复数据，或改为使用可以可靠还原的历史价格和成交量条件。

### 第二阶段：用同一套研究引擎研究币安做空

只有第一阶段证明 AI 能自主完成研究闭环，再接入币安现货与合约数据，研究上市后做空机会。

需要独立检验实际可做空时间、资金费率、交易费用、滑点和退市样本，避免只看到下跌的币，却忽略无法实际交易的机会。

### 第三阶段：再考虑 Harness²

如果 RD-Agent 能研究，但仍然反复犯同一种错误，再研究引入 Harness² 的自我改进机制。

如果你需要更严格的实验管理，也可以先借鉴 AI Scientist v3 的封闭最终评估和消融实验设计，不必整套迁移。

这次先不开发、不安装、不借鉴代码。

**先把开源项目当作一个黑盒拆开，弄清楚内部谁负责什么、谁调用谁、数据怎么流动、实验结果如何影响下一轮决策。** 看懂以后，再判断哪些机制值得使用。

上次的问题就在于：没有完成架构审查，就直接进入实现。结果虽然程序跑了很多轮，但你仍然需要不断纠正研究方向。

这次必须先回答五个问题：

1. **谁提出研究假设？** 是 AI 自己发现问题，还是人提前规定？
2. **谁决定下一步？** 是固定流程，还是 AI 根据上一轮结果自主选择？
3. **谁执行实验？** AI 直接运行代码，还是调用独立的执行器？
4. **谁评价结果？** AI 自己评价自己，还是有独立的、不能随意修改的评价标准？
5. **谁负责长期学习？** 失败经验存在哪里，下次研究如何调用，是否真的会改变决策？

其中第 4 和第 5 个问题最关键。没有可靠评价器，自主研究容易变成自动过拟合；没有有效的研究记忆，就只是反复运行实验。

## 二、最关键的遗漏：谁有权改变什么？

| 组件 | 可以改变 | 不应该允许改变 |

## 三、AI Scientist v3 与 Harness² 的关键区别

这次发现了两个需要特别重视的细节。

**AI Scientist v3：** 官方明确使用独立容器运行各阶段，并通过封闭评价器执行最终评估。其变体实验还会使用隔离网络环境和受控运行依赖。这个机制比单纯让 AI 自己评价策略更适合你的研究。<Cite refs={["turn868961search0","turn868961search3"]}/>

**Harness²：** 官方明确指出，它在任务内部的 Propose–Probe–Compose 过程中，可以不依赖真实答案反馈，而通过执行差异改进 Agent 工作方式。此外，项目还提醒：Codex 执行器可能关闭沙箱，网络访问不受限制，评测前需要额外隔离。<Cite ref="turn868961search2"/>

这意味着：

- AI Scientist v3 更适合借鉴**实验隔离和评价机制**。
- RD-Agent 更适合研究**如何自主生成下一轮假设**。
- Harness² 更适合研究**如何改善 Agent 自身的工作方法**。

但它们解决的不是同一个问题。

2. **进化搜索 Agent**：保留成功方案，淘汰失败方案，独立探索多条路径。
3. **决策执行框架**：管理研究状态、工具调用、长期记忆和停止条件。

## 五、最终判断：应该借鉴哪个？

我不建议直接安装一个庞大的框架，然后让它跑 500 轮。你上次遇到的问题恰恰说明：**先明确系统如何决策、如何验证，再决定借用哪些代码。**

| 你需要的能力 | 优先借鉴 | 要验证什么 |
|---|---|---|
| 独立提出金融假设 | RD-Agent | 是否真正生成不同的可检验假设 |
| 500 轮迭代与方案竞争 | OpenEvolve | 能否保留最佳方案和完整历史 |
| 审核每轮为什么改变 | AIDE | 实验树、代码、指标是否可追溯 |
| 反证与独立终局测试 | AI Scientist v3 | 能否隔离最终测试数据 |
| 长时间可靠运行 | LangGraph | 能否断点恢复、避免重复执行 |

### 我建议的实施顺序

先只做 **20 轮最小实验**，使用同一份冻结数据、同一个评分器，比对 AIDE 和 OpenEvolve 的搜索能力。

验收时必须看到每轮的假设、代码差异、实验数据、评估结果、保留或淘汰原因，并能从记录中复现。如果连 20 轮都无法正确解释，就不进入 500 轮。

通过后再扩大到 100 轮、500 轮，并将最终测试集封存。否则 AI 会在数百轮优化中反复适配历史噪声，最终得到一个历史表现极好、真实市场表现很差的策略。

**目前完成的是 GitHub 仓库、公开文档、迭代机制与部分基准成绩的核查；尚未对这些项目进行本地安装、源码逐函数审计或实际复现实验。**

我的优先顺序是：**先深入审核 OpenEvolve + AIDE 的决策机制，再借用 RD-Agent 的金融研究流程。** 这比直接复制一整个项目更符合你要的可理解、可验证、自主循环研究系统。

当前最有价值的改进，是让 AI 每轮都能够自主完成：

研究假设 → 实验 → 反证 → 失败归因 → 新假设 → 下一轮实验。

同时由独立的评估器管理样本外数据，防止 AI 在反复修改中把验证集也拟合掉。

**最终判断：** Minara 证明了这种产品架构已经有较完整的设计，但没有证明它能持续自主发现盈利策略。它适合作为架构参考，尚不适合作为无需审核就能直接接管资金的成熟系统。
